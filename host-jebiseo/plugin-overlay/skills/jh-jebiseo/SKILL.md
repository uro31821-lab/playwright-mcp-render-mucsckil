# 제비서 — 선택한 글로 Gemini에 전달

[JH 공통 허브](../jh-assistant-hub/SKILL.md)의 현재 목표·작업 ID·문맥을 이어받는다. 최신 사용자 지시를 적용한다. ‘제비서를 만들어줘’는 기존 개발도구로 보내며 개발·사용법·인용·부정만으로 휴대폰이나 외부 질의를 실행하지 않는다.

[공통 표시](../jh-assistant-hub/references/assistant-attribution.md)를 따른다. 실제 Gemini 응답을 얻어 현재 질문과 대조한 경우에만 그 기여를 **🏴‍☠️ 제비서:**로 표시한다. GPT가 준비한 요청·수동 안내에는 현재 담당을 표시하며 GPT 답을 Gemini 의견으로 꾸미지 않는다. **비서 배지와 설명은 전달 문장 밖에 둔다.**

## 기본 방침

- 휴대폰만 사용하며 **왼쪽 GPT / 오른쪽 Gemini**를 유지한다.
- 기본은 **전달할 문장을 선택 → ‘Gemini에게 물어보기’**다. 별도의 자동 OPEN·입력·실행을 동시에 붙이지 않는다.
- **유튜브 분석은 완료 후 분석 내용을 사용자가 선택·공유해 현재 GPT 대화에서 이어가는 순서까지 기본으로 안내한다.** 별도 ‘반환해 줘’ 요청을 다시 요구하지 않는다.
- 삼성 앱·기기와 영상 결과는 Gemini에서 확인한다. 이 두 기능은 사용자가 원한 때만 GPT 수동 공유를 안내한다. 모든 기능의 자동 답변 수집·영상 export·자동 GPT 반환은 하지 않으며 단계별 완료 회신을 요구하지 않는다.

| 기능 | 준비할 요청 |
| --- | --- |
| `ANDROID` — 삼성 앱·기기 | 현재 사용자가 요청한 대상·동작·필요 내용. 일정·노트·계산기·알람·연결 기기는 예시이며 실제 Gemini가 지원·연결하는 전체 범위 |
| `YOUTUBE` — 유튜브 분석 | 현재 요청의 영상 링크·분석 질문을 준비하고 분석 완료 후 수동 공유로 GPT에서 이어가기 |
| `VIDEO` — 영상 생성 | 현재 요청의 제작 프롬프트. 기존 구독 포함 범위·추가 결제 없음 |

‘계산기 열어 줘’ 같은 직접 요청에는 따로 추출할 일정·문서가 없어도 된다. 모든 삼성 기기의 실제 지원·연결을 추정하지 않는다. 영상 한도 소진을 API·업그레이드·추가 구매로 대체하지 않는다.

## 현재 요청에서 진행한다

1. 현재 요청에 필요한 대상·동작·내용만 준비한다. 다른 방의 대화·전체 기억·파일을 자동 전달하지 않는다. 준비 때문에 휴대폰 BEGIN_COMMAND를 만들지 않는다.
2. 기존 task에 pending/unknown이나 `requiresResultInspection:true`가 있으면 원 결과·현재 화면부터 확인한다. 선택 메뉴·새 task·전달 방식 변경·사용자 보고로 같은 효과를 재실행하지 않는다.
3. 기본 전달 방식은 `TEXT_SELECTION`이다. **Gemini에 보낼 문장만 독립된 한 덩어리**로 보여 주고, 그 밖에 선택 메뉴 사용법을 짧게 안내한다. 메뉴 이름은 사진에서 확인한 **‘Gemini에게 물어보기’**를 사용한다.
4. 선택 후에는 Gemini가 받은 요청을 확인하도록 안내한다. 초안으로 남아 있을 때만 실행하고 이미 응답 중이거나 결과가 있으면 다시 입력·전송하지 않게 한다. 기존 OPEN → INPUT → SUBMIT 순서를 선택 메뉴에 강제로 적용하지 않는다.
5. 진행 상황과 결과를 Gemini에서 확인하게 한다. **YOUTUBE는 분석 완료 후 결과를 선택·공유해 현재 GPT 대화로 가져오는 절차도 첫 안내에 포함한다.** ‘열었어/입력했어/됐어’ 같은 회신은 선택 사항이며 사용자 보고를 실제 전송·GPT 수신·작업 완료로 승격하지 않는다.

선택 메뉴의 표시만으로 내부 Intent, 실제 제출 범위, 오른쪽 배치를 확정하지 않는다. 왼쪽 GPT / 오른쪽 Gemini 요구는 유지하되 실제 열린 위치는 별도로 확인한다. 이 안내가 새 GPT 버튼·새 APK 기능·메뉴 자동 클릭 기능을 만들었다고 말하지 않는다.

## 유튜브 분석의 GPT 복귀와 다른 결과의 선택적 공유

YOUTUBE는 Gemini 분석이 끝난 뒤 실제 공유 목록이나 사용자가 확인한 메뉴를 이용해 분석 내용을 GPT로 가져오도록 안내한다. 별도 반환 요청을 다시 받지 않는다. 삼성·영상 결과는 사용자가 원한 때만 같은 수동 공유를 안내한다. 보지 않은 ‘ChatGPT에게 보내기’ 항목을 만들거나 자동 결과 회수를 시작하지 않는다.

**현재 GPT 대화에 실제 분석 내용이 들어왔는지 확인한 뒤** 비교·재정리를 이어간다. 공유 동작이나 사용자 보고만으로 현재 대화 자동 복귀·삽입·수신을 보장하지 않는다. 사용자가 유튜브 반환 안내를 끄면 그 선택을 따른다.

## 호스트 API와 기존 열기 경로

현재 호스트에 후보 API가 실제 연결돼 있으면 `createHandoffRuntime({request,deliveryMode:'TEXT_SELECTION',requiresResultInspection,deviceId?,commandId?})`를 사용한다. request는 준비 함수에 넣는 **원 의미 입력**이며 준비 완료 객체가 아니다. 전달 옵션을 request 안에 넣지 않는다. 없는 MCP 도구·mode·승인을 만들어 호출하지 않는다.

`presentation()`으로 준비 문장과 남은 절차를 함께 표시한다. `reportManualProgress()`의 OPEN·INPUT·SUBMIT 및 선택 경로의 HANDOFF 보고는 선택적이며 진행을 뒤로 돌리지 않는다. `session.prepareManualReturn()`의 requested 생략 기본값은 YOUTUBE에서 true, ANDROID·VIDEO에서 false다. `requested:false`면 안내를 끄고 다른 기능의 명시적 요청에는 `requested:true`를 사용한다. YOUTUBE의 `returnToGpt:true`는 수동 복귀 의도이며 모든 기능의 `automaticReturnToGpt:false`와 실제 미수신 상태를 유지한다. 상세 계약은 [제공자 계약](references/provider-contract.md)을 따른다.

`OPEN_MANUAL`을 명시적으로 선택하면 기존 웹 OPEN 1회·같은 원 job 조회 후 수동 진행을 사용한다. YOUTUBE·VIDEO의 기존 대상은 `https://gemini.google.com/app`이며 현재 유효한 명령·기기·원 승인 범위를 지킨다. 삼성 작업은 Gemini 모바일 앱을 여는 단계부터 수동 안내한다. 웹을 열었다는 사실을 삼성 모바일 연동 증거로 사용하지 않는다.

‘제미나이 열어줘’라는 `intent:open`은 프롬프트 없이 화면만 여는 별도 요청이다. 분석·전송·영상 생성을 덧붙이지 않는다. 이미 시도한 OPEN이 불명확하면 원 결과를 먼저 확인하고 같은 열기를 반복하지 않는다.

## 가용성·원본 보호·적용 범위

선택 안내·유튜브 기본 수동 복귀·다른 결과의 요청된 수동 반환 안내에 전체 `gemini-assistance` 가용성을 요구하지 않는다. 실제 자동 Gemini 의견 회수에는 기존 `scripts/availability.mjs`와 신뢰된 제공자 상태 검사를 유지한다. 준비 가능성으로 실제 자동 협업·Gemini 응답 성공을 만들어 내지 않는다.

원 command·영수증·기기·세션·pending·발급된 폼 인자 보호를 유지한다. 보관 APK의 화면 복원 가능성이 있는 snapshot을 순수 선택 안내의 선행 읽기로 호출하지 않는다. 확인되지 않은 자동 효과를 수동 안내로 우회하지 않는다.

에비서·깃비서의 독립 분석은 병렬로 진행할 수 있다. 같은 휴대폰의 실제 동작은 한 담당이 원 작업·명령·영수증을 유지하며 순서대로 처리한다.

개발 기준은 **Stage72 / PR #159 (`5d72b78fd3730111076b33e2771f5b6b70f657aa`), Stage62 FIX3 APK 유지 + Stage71 Android → Manual**이다. 기존 직접 세 패키지 OPEN_APP·reply-proof·영상 파일 검증은 별도 호환 기반이며 이번 전달의 선행 조건이 아니다.

이번 수정은 Git 후보의 overlay다. 설치된 플러그인·다른 방이 즉시 갱신되거나 실제 휴대폰 전달에 성공했다고 표시하지 않는다. 후보·준비·안내·사용자 보고·독립 검증을 구분하며 소스와 검사만으로 `productionRegistered`, `geminiAssistanceAvailable`, `liveExecutionVerified`를 true로 올리지 않는다.
