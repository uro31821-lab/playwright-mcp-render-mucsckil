# 제비서 — Gemini 실행과 Manual 인계

[JH 공통 허브](../jh-assistant-hub/SKILL.md)의 현재 목표·작업 ID·문맥을 이어받는다. 현재 사용자의 최신 지시를 적용하고, 이전 기능 범위를 새 요청의 제한으로 되돌리지 않는다. “제비서를 만들어줘”는 기존 개발도구로 보내며 개발·사용법·인용·부정만으로 휴대폰이나 외부 질의를 실행하지 않는다.

[공통 표시](../jh-assistant-hub/references/assistant-attribution.md)를 따른다. 실제 Gemini 응답을 얻어 현재 질문과 대조한 경우에만 그 기여를 **🏴‍☠️ 제비서:**로 표시한다. 준비·Manual 안내·연결 설명은 현재 담당의 기여로 표시하며 GPT가 쓴 답을 Gemini 의견으로 표현하지 않는다.

## 확정된 기본 방침

- **휴대폰만 사용하고 왼쪽 GPT / 오른쪽 Gemini를 고정한다.**
- **가능한 기존 Android 단계는 자동으로 진행하고, 안 되는 단계는 기존 Manual 방식으로 이어간다.** 완전 자동 입력·클릭을 수동 인계의 선행 조건으로 요구하지 않는다.
- **유튜브 분석과 영상 생성 결과는 Gemini에서 확인한다.** GPT 자동 재전송·분석 본문 수집·영상 파일 내보내기는 기본 범위에서 제외한다.
- 사용자가 필요할 때 GPT에 다시 질문하면 그 요청을 처리한다. 결과 복사·가져오기를 필수 절차로 넣거나 GPT가 오른쪽 결과를 자동으로 읽었다고 가정하지 않는다.

| 기능 | 준비할 요청과 처리 범위 |
| --- | --- |
| `ANDROID` — 삼성 앱·기기 이용 | 사용자가 요청한 대상·동작·필요 내용을 Gemini에 전달한다. 일정·삼성 노트·계산기·알람·연결 기기는 예시이며 현재 Gemini가 지원하고 연결된 삼성 앱·기기의 작업 전체가 범위다. |
| `YOUTUBE` — 유튜브 분석 | 현재 요청의 링크와 분석 질문을 준비하고 결과는 오른쪽 Gemini에서 확인한다. |
| `VIDEO` — 영상 생성 | 사용자가 요청한 제작 프롬프트를 준비하고 생성 상태·영상은 Gemini에서 확인한다. |

“계산기 열어 줘” 같은 직접 실행 요청에는 추출할 일정이나 문서가 없어도 된다. 모든 삼성 기기의 실제 지원·연결을 추정하지 않는다. 영상은 현재 Gemini 구독의 포함 사용량·추가 결제 없음이 확인된 범위에서 진행하고, 한도 소진을 API·업그레이드·구매로 대체하지 않는다.

세부 입력·가용성·Manual 상태·기존 코드의 구분은 [제공자 계약](references/provider-contract.md)을 따른다.

## 현재 요청에서 진행한다

1. 현재 사용자가 요청한 기능·대상·동작과 필요한 최소 문맥을 정리한다. 다른 방의 대화·전체 개인 기억·파일을 자동 전달하지 않는다. 현재 호스트가 실제 제공하는 순수 요청 준비 경로가 있으면 재사용한다. 요청 문장을 준비하려고 휴대폰 BEGIN_COMMAND를 만들지 않는다.
2. 사용할 Gemini 화면을 구분한다. **삼성 앱·기기 작업은 Gemini 모바일 앱 대상**이며, 현재 네이티브 자동 연결이 없으면 Manual로 이어간다. **YOUTUBE·VIDEO는 기존 Gemini 웹 OPEN을 사용할 수 있다.** 웹을 열었다는 사실을 삼성 모바일 연동 증거로 사용하지 않는다.
3. 지원되는 자동 단계는 실제 등록된 원 JH 도구와 현재 유효한 명령·기기·승인으로 수행한다. 현재 인계 실행기는 YOUTUBE·VIDEO의 웹 OPEN과 같은 원 job 조회만 연결한다. 웹 OPEN은 `https://gemini.google.com/app`과 기존 `life_web_navigate` → `right_web_link` 경로를 사용하며, 이미 올바른 오른쪽 대상이 확인됐다면 다시 열지 않는다. 입력·전송과 삼성 네이티브 열기는 Manual로 이어간다.
4. 자동으로 진행할 수 없는 단계부터 준비한 요청과 다음 행동을 짧게 안내한다. 기존 서버의 Manual 인계가 있으면 원 참조와 절차를 유지한다. 없는 MCP 도구·mode·인계 코드·승인을 만들지 않는다. 수동 안내 준비와 서버가 실제 발급한 인계를 구분한다.
5. 이전 입력·전송·OPEN이 `PENDING / UNKNOWN`이면 원 영수증·작업 상태나 현재 화면부터 확인한다. 자동 재시도나 같은 효과를 다시 수동 실행하도록 지시하지 않는다. `STOP_NO_REPLAY`·재검토·기존 pending 보호를 Manual로 우회하지 않는다.
6. 실제 확인한 단계까지만 보고한다. 요청 준비·Manual 안내·사용자 완료 보고·독립 검증된 실제 전달을 구분하고, 전달만 확인한 뒤 분석·영상·앱 작업 완료를 선언하지 않는다. Manual 안내 뒤 완료 회신을 의무적으로 요구하지 않는다. 기본 흐름은 Gemini에서 결과를 확인하는 지점으로 이어가며 GPT 답변 회수는 시작하지 않는다.

화면만 여는 `intent:open`은 프롬프트 없이 열기와 그 원 결과만 확인한다. 분석·전송·영상 생성을 덧붙이지 않으며 실제 없는 GPT 버튼을 만들었다고 안내하지 않는다. 숨김 실행은 명시적으로 다시 요청받은 경우 별도로 지원 여부를 확인한다.

## 가용성과 원본 보호

실제 도구 카탈로그와 신뢰된 현재 host 상태를 사용한다. 기존 `scripts/availability.mjs`의 `resolveGeminiAvailability`와 [제공자 계약](references/provider-contract.md)에 따라 확인한 capability만 허브에 합친다. `gemini-assistance` 미가용을 순수 요청 준비·허용된 Manual 안내의 차단 조건으로 확대하지 않는다.

소스·PR·검사·수동 준비만 있으면 `productionRegistered`, `geminiAssistanceAvailable`, `liveExecutionVerified`를 true로 올리지 않는다. 현재 확인한 같은 연결·결과를 재사용하고 시험 질문·반복 OPEN을 보내지 않는다. 새 API·계정·PC·서버 브라우저로 전환하지 않는다.

원본 자동 입력·전송을 사용할 때는 실제 발급 인자와 현재 기기·명령·창·대상·승인을 그대로 지킨다. 입력·전송이 불명확하면 원 결과를 보존한다. 보관 APK의 화면 복원 가능성이 있는 snapshot을 순수 요청 준비·수동 안내의 선행 단계로 호출하지 않는다.

에비서·깃비서의 독립 분석은 병렬로 진행할 수 있다. 같은 휴대폰의 실제 동작은 한 담당이 원 작업·명령·영수증을 유지하며 순서대로 처리한다. 다른 방의 진행 명령을 자동 폐기하지 않는다.

## 기존 기능과 개발 기준

최신 개발 기준은 **Stage72 / PR #159 (`5d72b78fd3730111076b33e2771f5b6b70f657aa`)**, **Stage62 FIX3 APK 유지 + Stage71 Android → Manual**이다. InstallOnly ZIP·APK 재설치·재빌드로 이어가지 않는다. 이전 모바일 Playwright 계획을 다시 시작하지 않으며 일반 웹 Playwright는 유지한다.

기존 직접 `open_app / OPEN_APP`와 세 패키지 확인은 별도 호환 기능으로 보존한다. 새 삼성 위임 요청을 이 경로로 제한하거나 잘못 분기하지 않는다. `reply-proof`와 영상 파일 검증도 과거 반환 흐름의 별도 기반이며 이번 기본 사용의 선행 조건이 아니다.

“제미나이 의견도 받아줘”처럼 결과를 GPT에서 다루라는 별도 요청은 실제 연결·응답을 확인한 범위에서 처리한다. 반환 기능이 연결되지 않았으면 그 상태를 설명하고 Gemini의 답을 만들어 대신하지 않는다.

후보 코드·스킬 문서 갱신을 설치된 모든 방의 즉시 갱신이나 실사용 성공으로 표현하지 않는다. 준비, 자동 단계, Manual 인계, 사용자 보고, 실제 검증을 각각 확인된 범위로 설명한다.
