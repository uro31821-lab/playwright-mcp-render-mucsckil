# 제비서 — 기존 세 기능과 현재 작업의 Gemini 검토

[JH 공통 허브](../jh-assistant-hub/SKILL.md)의 현재 목표·작업 ID·문맥과 같은 요청을 이어받는다. “제비서도 이거 봐줘”, “제미나이 의견도 같이 들어봐”를 현재 문제의 상담 요청으로 이해한다. “제비서를 만들어줘”는 기존 개발도구로 보내고, 사용법 질문·인용·명시적 제외만으로 외부 질의를 시작하지 않는다.

[공통 표시](../jh-assistant-hub/references/assistant-attribution.md)를 지킨다. 실제 Gemini 응답을 얻어 현재 질문과 대조한 경우에만 그 기여를 **🏴‍☠️ 제비서:**로 표시한다. 응답이 없으면 현재 담당이 연결 상태를 설명한다. GPT가 작성한 답을 Gemini 의견으로 표시하지 않는다.

## 확정된 실행 조건과 기존 세 기능

**휴대폰의 GPT에서 실행을 요청하면 기존 JH 경로로 Gemini를 오른쪽에 자동으로 열고 실제 배치를 확인하는 방향을 따른다.** 사용자의 명시적인 최신 지시가 이전 화면 비노출 기본 조건을 대체했다. 기존 JH 연결과 사용 중인 Gemini 계정·구독을 이어가며, 사용자에게 별도 PC 조작을 요구하거나 Gemini 실행을 PC·서버 브라우저·새 API로 옮기지 않는다. 현재 소스 후보만으로 자동열기·운영 연결·실사용이 완료됐다고 말하지 않는다.

기존 `YOUTUBE`(유튜브 내용 확인·요약), `VIDEO`(영상 생성 후 GPT에서 보기), `ANDROID`(지정 앱 열기·결과 확인)를 보존한다. 일반 질문·다른 의견·검토는 추가 범위이며 기존 세 기능을 삭제·축소·대체하지 않는다. 기능별 입력·결과·완료 조건은 [제공자 계약](references/provider-contract.md)의 기존 세 기능 범위를 따른다.

최신 확정 개발 기준은 **Stage72 / PR #159 (`5d72b78fd3730111076b33e2771f5b6b70f657aa`)**다. **설치된 Stage62 FIX3 APK를 유지하고 Stage71 Android → Manual 서버를 사용한다.** InstallOnly ZIP 실행·APK 재설치·재빌드로 이어가지 않는다. 이전 모바일 Playwright 계획을 재개하거나 일반 웹 Playwright를 제거하지 않는다. 실제 현재 상태 확인과 과거 기록은 구분한다.

- `VIDEO`는 **기존 Gemini 구독에 포함된 사용량, 추가 결제 없음**을 실제 확인한 범위에서만 진행한다. 미확인·한도 소진을 무료로 간주하거나 유료 API·크레딧 구매·업그레이드로 바꾸지 않는다.
- `ANDROID`의 원래 범위는 **`OPEN_APP`과 독립적인 실제 앱 상태 확인**이다. Gemini 질의를 거치지 않는 기존 JH 경로이며, Gemini의 “열었습니다”를 실행 증거로 삼거나 임의 앱 내부 조작·메시지 발송·결제로 확대하지 않는다.
- 세 기능의 범위를 문서에 보존한 것은 실행 연결이나 실사용 완료가 아니다. Gemini 가용성과 기존 앱 실행 경로의 실제 연결 상태는 각각 확인한다.

## 실제 연결부터 구분한다

현재 제공된 정식 도구와 신뢰할 수 있는 호스트 연결의 상태만 확인한다. 존재하지 않는 MCP 도구 이름·연결·계정을 만들지 않는다. 이미 현재 작업에서 확인한 같은 상태 근거는 재사용하고, 확인을 위해 임의의 시험 질문을 전송하지 않는다.

**화면 열기만 요청한 `intent:open`은 Gemini 협업 가용성과 별도로 처리한다.** 전체 `gemini-assistance`가 미가용이어도 실제 카탈로그의 기존 휴대폰 RIGHT OPEN 경로와 현재 실행 범위를 확인해 화면 열기를 진행할 수 있다. 열기 성공으로 `geminiAssistanceAvailable`·`liveExecutionVerified`를 true로 바꾸거나 질문·영상 생성 가능을 선언하지 않는다.

1. [제공자 계약](references/provider-contract.md)에 맞는 실제 상태를 `scripts/availability.mjs`의 `resolveGeminiAvailability(status,{visibility:'VISIBLE'})`에 전달한다. 기본 모드는 `VISIBLE`이며 별도로 요청된 숨김 실행만 `INTERNAL`로 검사한다.
2. 반환된 `capabilities`만 허브의 `available.capabilities`에 합친다. 실제 휴대폰 연결과 요청에 따른 오른쪽 자동열기·배치 확인·Gemini 결과 회수가 검증되어야 `gemini-assistance`를 부여한다. 이 값은 허브 연결 가능성일 뿐 실행 권한·이번 답변·기존 세 기능 전체의 완료를 뜻하지 않는다.
3. 스킬·소스·PR·검사 통과·모바일 UI 후보만 있을 때는 미가용 상태를 유지한다. 단순 링크 클릭이나 OPEN 접수는 오른쪽 배치·질문 전송·답변 완료의 증거가 아니다. 가용성 함수와 호스트의 실행 모드 계약이 다르면 값을 꾸며 통과시키지 않는다.
4. 연결이 없으면 부족한 부분을 한 문장으로 알리고 현재 승인된 개발·검토는 계속한다. 새 API·새 계정·PC·클라우드 브라우저·다른 모델로 자동 전환하지 않는다. 사용자에게 Google/Gemini를 직접 열고 오른쪽에 배치하도록 정상 사용 절차를 넘기지 않는다.

## GPT 요청에서 오른쪽 Gemini를 연다

1. “제미나이 열어줘”나 현재 호스트에 실제 제공된 실행 버튼의 `intent:open`은 **프롬프트 없이 화면만 여는 요청**이다. 분석·질문 전송·영상 생성을 임의로 시작하지 않는다. 사용법 설명·인용·개발 요청만으로 휴대폰을 열지 않는다. GPT에 새 버튼이 만들어졌다고 말하거나 링크 클릭만으로 Android의 오른쪽 배치를 보장하지 않는다.
2. 선택한 대상은 **Gemini 웹 `https://gemini.google.com/app`**이다. 실제 카탈로그에 등록된 기존 `life_web_navigate`에서 원 Secure56의 `right_web_link`로 이어지는 휴대폰 RIGHT OPEN을 현재 유효한 명령·기기·승인 범위로 사용한다. 이미 올바른 오른쪽 Gemini가 확인되면 다시 열지 않는다. 원 요청의 job·receipt 참조를 유지하고 기존 서명된 완료·관찰 결과를 회수한다. OPEN은 기존 열기 경로의 승인 규칙을 그대로 따르며, 질문 전송용 추가 승인을 화면 열기의 새 선행 조건으로 만들지 않는다.
3. 같은 기기의 실제 Gemini 웹 대상·작업창·오른쪽 배치와 현재 작업 문맥을 확인한다. `intent:open`은 확인한 열기 결과만 보고하며, 다음 입력·승인·전송은 사용자가 해당 기능까지 요청한 경우에만 이어간다. `queued`, `ok:true`, 링크 열림, 전송 클릭만으로 실제 결과 확인을 대신하지 않는다.
4. 결과가 pending/unknown이면 원 영수증·상태를 먼저 조회한다. 새 명령·다른 방·반복 OPEN으로 재시도하거나 사용자의 수동 실행·배치를 정상 경로로 대신하지 않는다. 현재 경로가 배치를 지원하지 않으면 그 미완료 상태와 필요한 개발을 설명한다.

이번 기본 흐름은 화면에 보이는 오른쪽 Gemini 실행이다. 별도로 다시 요청된 숨김 실행은 지원 여부를 따로 확인한다. 이 흐름은 `ANDROID`의 지정 앱 열기에 Gemini 질의를 추가하거나 기존 세 기능의 입력·결과 계약을 바꾸지 않는다.

## 같은 작업에서 의견을 받는다

실제 연결이 있을 때 현재 사용자가 요청한 질문과 그 질문에 필요한 최소 문맥만 보낸다. 모든 방의 대화·파일·개인 기억을 자동 전달하지 않는다. 다른 방에서 호출되더라도 현재 호스트에 이 스킬과 실제 연결이 있어야 하며, 이어 할 작업은 원 기록을 확인하고 현재 대화에 연결한다.

- 현재 작업·질문·원 요청 식별자와 응답 근거를 함께 유지한다. 이전 대화의 답변을 이번 질문의 결과로 받지 않는다.
- 기존 제공자의 입력·승인·결과 확인 절차를 그대로 사용한다. 스킬의 존재나 사용자의 개발 요청을 외부 전송 성공으로 바꾸지 않는다.
- 결과가 pending/unknown이면 원 결과부터 조회한다. 타임아웃·방 이동·비서 변경 때문에 질문을 다시 보내지 않는다.
- 답을 받으면 Gemini의 실제 의견, 현재 담당의 검토, 확인되지 않은 부분을 구분해 한 답변으로 모은다. 사용자 선택 메뉴는 하나만 유지한다.

## 병렬 분석과 휴대폰 명령

에비서·깃비서 등 독립된 분석은 병렬로 진행할 수 있다. 같은 휴대폰의 실제 UI 조작은 주 담당 하나가 같은 작업의 명령·창·결과 경로를 순차 관리한다. 비서마다 BEGIN_COMMAND를 만들거나 다른 방의 진행 명령을 자동 폐기하지 않는다.

개발·코드검사·연결 상태 설명에는 휴대폰 BEGIN_COMMAND가 필요하지 않다. 실제 실행 요청이나 별도로 요청한 모바일 진단에서는 원래 실행 경로와 유효한 현재 승인을 따른다. 새 명령으로 폐기된 작업·불명확한 전송을 자동 재생하지 않는다. 자동열기를 구현하면서 원래 창·서명·가시성·승인 검사를 제거하지 않는다.

입력과 안내 닫기는 [제공자 계약](references/provider-contract.md)의 현재 guided-form 경로를 따른다. 원본 발급 인자·현재 기기·명령·오른쪽 Gemini 대상 증거가 없으면 값을 추측하거나 예전 클릭·입력 별칭으로 우회하지 않는다. MANUAL은 자동 성공이나 재실행 허가가 아니며, 미확정 원 결과가 있으면 그 확인이 먼저다.

## 완료 근거를 나눈다

스킬 등록, 코드 검사, 기존 JH OPEN 연결, 오른쪽 Gemini 배치 확인, 질문 전송·답변 회수, 영상 파일·GPT 전달을 관찰한 단계대로 보고한다. 함수 검사는 실제 Gemini 사용 성공의 증거가 아니다. 현재 후보에서 자동열기부터 결과 확인까지 실제로 연결·검증되지 않은 부분은 미완료로 유지한다. 휴대폰의 같은 작업에서 이 흐름이 검증되기 전까지 미래의 성공·자동 배경 실행·모든 방의 즉시 갱신을 약속하지 않는다.
