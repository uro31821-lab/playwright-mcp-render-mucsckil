# 제비서 — 요청문 선택·Gemini 메뉴 클릭·실행 클릭

[JH 공통 허브](../jh-assistant-hub/SKILL.md)의 현재 목표·작업 ID·문맥을 이어받는다. 최신 사용자 지시를 적용한다. ‘제비서를 만들어줘’는 개발 요청이며 그 예문을 휴대폰에서 실행하지 않는다.

[공통 표시](../jh-assistant-hub/references/assistant-attribution.md)를 따른다. 실제 Gemini 응답을 얻어 현재 질문과 대조한 경우에만 그 기여를 **🏴‍☠️ 제비서:**로 표시한다. GPT가 작성한 전달문·진행 설명에는 현재 담당을 표시하며 **비서 배지와 설명은 전달문 밖에 둔다.**

## 최신 핵심 요구

휴대폰의 **왼쪽 GPT / 오른쪽 Gemini** 배치를 유지한다. 기본 `AUTO_TEXT_SELECTION`은 다음 세 동작을 실제 실행기로 처리한다.

1. 왼쪽 GPT에 표시된 정확한 요청문을 선택한다. 지원되는 네이티브 노드의 선택 API를 이용하며 실제 시작·끝 범위와 원문을 확인한다. 제스처가 전달됐다는 이유만으로 선택 성공으로 처리하지 않는다.
2. 선택된 글에 속한 실제 **‘Gemini에게 물어보기’** 메뉴를 클릭한다. 오른쪽 Gemini에 같은 요청문이 초안으로 들어왔는지 확인한다.
3. 오른쪽 Gemini의 실제 실행 버튼을 클릭한다. 기존 Gemini 초안·전송 대상 검토와 원래 휴대폰 승인 절차를 사용한다. 제출 관찰과 실제 삼성 작업·분석·영상 완료는 구분한다.

자동 연결이 없거나 현재 UI를 검증할 수 없으면 그 단계가 미지원·미확정임을 알린다. 수동 사용법만 만든 뒤 세 동작을 구현했다고 말하지 않는다. `TEXT_SELECTION`과 `OPEN_MANUAL`은 명시적으로 선택한 대안이며 자동 오류를 감추는 성공 상태가 아니다.

## 세 가지 요청과 결과

| 기능 | 보낼 내용 | 결과 |
| --- | --- | --- |
| `ANDROID` | 현재 요청의 삼성 앱·기기 대상, 동작, 필요한 내용. 일정·노트·계산기·알람은 예시 | Gemini와 실제 대상에서 확인 |
| `YOUTUBE` | 현재 요청의 정확한 영상 링크와 분석 질문 | 분석 후 실제 결과를 사용자가 선택·공유해 현재 GPT에서 이어가기 |
| `VIDEO` | 현재 요청의 제작 프롬프트. 기존 구독 포함 범위, 추가 결제 없음 | Gemini에서 생성 상태·영상 확인 |

모든 삼성 기기의 지원·연결을 추정하지 않는다. 영상 한도 소진을 API·업그레이드·추가 구매로 대체하지 않는다. 유튜브 결과의 GPT 복귀 요구는 유지한다. 현재 후보의 결과 복귀는 수동이며 자동 답변 회수는 아직 완성된 기능으로 표시하지 않는다.

## 실행 순서

1. 현재 요청에 필요한 내용만 준비한다. 다른 방의 대화·전체 기억·파일을 자동 전달하지 않는다. 준비 자체는 명령 발급이나 전송이 아니다.
2. 기존 task의 pending/unknown과 `requiresResultInspection`을 유지한다. 미확정 효과가 있으면 원 결과부터 확인하며 새 task·모드 변경·사용자 보고로 같은 전송을 반복하지 않는다.
3. 후보가 실제 적용된 서버에서는 기존 `life_android_step`의 `jebiseo_handoff_prepare` → `jebiseo_handoff_start` → 필요한 경우 `jebiseo_handoff_resume` broker를 사용한다. marker는 `__JH_JEBISEO_HANDOFF_BROKER_V1__`, value schema는 `JH_JEBISEO_AUTO3_BROKER_V1`이며 [제공자 계약](references/provider-contract.md)을 따른다. PREPARE의 request는 원 의미 입력이고, 후속 요청은 반환된 `nextArguments`와 같은 session 참조를 사용한다. 미적용 서버에 새 action을 임의로 호출하지 않는다.
4. **PREPARE가 반환한 `preparedPrompt`를 현재 GPT 화면에 독립된 선택 가능한 텍스트 블록으로 한 번 표시한 뒤 START를 호출한다.** 내부 호스트도 `presentation()` → 실제 화면 표시 → `start()` 순서를 지킨다. 동일 문장을 여러 번 표시하거나 설명·배지를 섞지 않는다. 아직 화면에 보이지 않는 문자열을 선택했다고 주장하지 않는다.
5. 서버와 앱이 선택 → 메뉴 → 실행을 순서대로 처리한다. `AWAITING_COMPLETION`에서는 같은 원 job 완료를 확인한다. 기존 휴대폰의 정확한 대상 승인이 필요하면 `AWAITING_APPROVAL`을 그대로 알리고, 승인 후 같은 broker/session의 RESUME로 내부 `resumeAutomation()`과 같은 requestId를 재개한다. 새 명령·새 클릭을 생성해 승인이나 미확정 결과를 우회하지 않는다.
6. `COMPLETED`도 제출 관찰까지의 상태다. 삼성 작업·분석·영상 완료나 GPT 결과 수신을 자동으로 의미하지 않는다. 읽지 않은 답변을 Gemini 결과로 작성하지 않는다.

유효한 현재 명령·기기·세션은 원 호스트에서 얻는다. 임의 명령 ID·영수증·승인 토큰·성공 callback을 사용하지 않는다. 실제 폰 실행은 한 담당이 순차 처리한다. 에비서·깃비서의 소스 검토는 병렬로 진행할 수 있다.

## 지원 범위와 적용 상태

이 후보는 네이티브 ChatGPT의 선택 가능한 단일 텍스트 노드, 원문과 선택 범위, 출처가 확인되는 선택 메뉴, 오른쪽 네이티브 Gemini 초안과 전송 버튼을 확인해야 한다. 브라우저 ChatGPT, 선택 범위가 노출되지 않는 화면, 전체 화면 Gemini·귀속 불명 팝업에는 자동 성공을 보장하지 않는다.

기존 Stage62 FIX3에는 왼쪽 GPT 요청문 선택 실행기가 없었다. 이번 기능에는 **새 Android 후보 코드가 필요**하다. 기존 설치본이 그대로 기능을 얻었다고 설명하지 않는다. 원래 서명 키·정식 설치 경로를 사용하며 서명 없는 빌드 산출물을 설치 가능한 완성본으로 제시하지 않는다.

기준은 Stage72 / PR #159 (`5d72b78fd3730111076b33e2771f5b6b70f657aa`), Stage62 FIX3 + Stage71 Android → Manual이다. 기존 일반 LEFT 클릭·입력 제한과 Secure56 서명·원 완료·durable 보호를 유지한다. 후보·서버 연결·APK 빌드·설치·실기기 성공을 별도로 보고한다. 실제 확인 전 `productionRegistered`, `geminiAssistanceAvailable`, `liveExecutionVerified`를 true로 올리지 않는다.

수동 경로·유튜브 반환·정확한 API는 [제공자 계약](references/provider-contract.md)을 따른다.
