# 제비서 — 기존 세 기능과 현재 작업의 Gemini 검토

[JH 공통 허브](../jh-assistant-hub/SKILL.md)의 현재 목표·작업 ID·문맥과 같은 요청을 이어받는다. “제비서도 이거 봐줘”, “제미나이 의견도 같이 들어봐”를 현재 문제의 상담 요청으로 이해한다. “제비서를 만들어줘”는 기존 개발도구로 보내고, 사용법 질문·인용·명시적 제외만으로 외부 질의를 시작하지 않는다.

[공통 표시](../jh-assistant-hub/references/assistant-attribution.md)를 지킨다. 실제 Gemini 응답을 얻어 현재 질문과 대조한 경우에만 그 기여를 **🏴‍☠️ 제비서:**로 표시한다. 응답이 없으면 현재 담당이 연결 상태를 설명한다. GPT가 작성한 답을 Gemini 의견으로 표시하지 않는다.

## 확정된 실행 조건과 기존 세 기능

**휴대폰만 사용하고 Gemini 화면 비노출을 유지한다.** 기존 JH 연결과 사용 중인 Gemini 계정·구독을 이어가며, 사용자에게 별도 PC 조작을 요구하거나 Gemini 실행을 PC·서버 브라우저·새 API로 옮기지 않는다. 비노출 경로가 없으면 그 부분은 미완료로 남기고 승인된 개발·검토를 계속한다.

기존 `YOUTUBE`(유튜브 내용 확인·요약), `VIDEO`(영상 생성 후 GPT에서 보기), `ANDROID`(지정 앱 열기·결과 확인)를 보존한다. 일반 질문·다른 의견·검토는 추가 범위이며 기존 세 기능을 삭제·축소·대체하지 않는다. 기능별 입력·결과·완료 조건은 [제공자 계약](references/provider-contract.md)의 기존 세 기능 범위를 따른다.

- `VIDEO`는 **기존 Gemini 구독에 포함된 사용량, 추가 결제 없음**을 실제 확인한 범위에서만 진행한다. 미확인·한도 소진을 무료로 간주하거나 유료 API·크레딧 구매·업그레이드로 바꾸지 않는다.
- `ANDROID`의 원래 범위는 **`OPEN_APP`과 독립적인 실제 앱 상태 확인**이다. Gemini 질의를 거치지 않는 기존 JH 경로이며, Gemini의 “열었습니다”를 실행 증거로 삼거나 임의 앱 내부 조작·메시지 발송·결제로 확대하지 않는다.
- 세 기능의 범위를 문서에 보존한 것은 실행 연결이나 실사용 완료가 아니다. Gemini 가용성과 기존 앱 실행 경로의 실제 연결 상태는 각각 확인한다.

## 실제 연결부터 구분한다

현재 제공된 정식 도구와 신뢰할 수 있는 호스트 연결의 상태만 확인한다. 존재하지 않는 MCP 도구 이름·연결·계정을 만들지 않는다. 이미 현재 작업에서 확인한 같은 상태 근거는 재사용하고, 확인을 위해 임의의 시험 질문을 전송하지 않는다.

1. [제공자 계약](references/provider-contract.md)에 맞는 실제 상태를 `scripts/availability.mjs`의 `resolveGeminiAvailability`에 전달한다.
2. 반환된 `capabilities`만 허브의 `available.capabilities`에 합친다. 실제 비노출 실행·Gemini 제공·종단 검증이 모두 확인된 때만 `gemini-assistance`가 나온다. 반환값은 실행 권한이나 실제 답변이 아니다.
3. 스킬·소스·PR·검사 통과·모바일 UI 후보만 있을 때는 미가용 상태를 유지한다. 오른쪽 Gemini 화면을 읽는 기능은 화면 비노출 지원의 증거가 아니다.
4. 연결이 없으면 부족한 부분을 한 문장으로 알리고 현재 승인된 개발·검토는 계속한다. 새 API·새 계정·PC·클라우드 브라우저·다른 모델로 자동 전환하지 않는다. 현재 후보의 `INTERNAL` 요청이 막히면 `VISIBLE`로 바꿔 실행하지 않는다.

## 같은 작업에서 의견을 받는다

실제 연결이 있을 때 현재 사용자가 요청한 질문과 그 질문에 필요한 최소 문맥만 보낸다. 모든 방의 대화·파일·개인 기억을 자동 전달하지 않는다. 다른 방에서 호출되더라도 현재 호스트에 이 스킬과 실제 연결이 있어야 하며, 이어 할 작업은 원 기록을 확인하고 현재 대화에 연결한다.

- 현재 작업·질문·원 요청 식별자와 응답 근거를 함께 유지한다. 이전 대화의 답변을 이번 질문의 결과로 받지 않는다.
- 기존 제공자의 입력·승인·결과 확인 절차를 그대로 사용한다. 스킬의 존재나 사용자의 개발 요청을 외부 전송 성공으로 바꾸지 않는다.
- 결과가 pending/unknown이면 원 결과부터 조회한다. 타임아웃·방 이동·비서 변경 때문에 질문을 다시 보내지 않는다.
- 답을 받으면 Gemini의 실제 의견, 현재 담당의 검토, 확인되지 않은 부분을 구분해 한 답변으로 모은다. 사용자 선택 메뉴는 하나만 유지한다.

## 병렬 분석과 휴대폰 명령

에비서·깃비서 등 독립된 분석은 병렬로 진행할 수 있다. 같은 휴대폰의 실제 UI 조작은 주 담당 하나가 같은 작업의 명령·창·결과 경로를 순차 관리한다. 비서마다 BEGIN_COMMAND를 만들거나 다른 방의 진행 명령을 자동 폐기하지 않는다.

개발·코드검사·연결 상태 설명에는 휴대폰 BEGIN_COMMAND가 필요하지 않다. 사용자가 별도로 요청한 모바일 진단에서만 원래 실행 경로와 유효한 현재 승인을 따른다. 새 명령으로 폐기된 작업·불명확한 전송을 자동 재생하지 않는다. 화면 숨김 요구를 충족하려고 원래 창·서명·가시성 검사를 제거하지 않는다.

## 완료 근거를 나눈다

스킬 등록, 코드 검사, 실제 제공자 연결, 질문 전송·답변 회수, 화면 비노출 실행을 관찰한 단계대로 보고한다. 함수 검사는 실제 Gemini 사용 성공의 증거가 아니다. 현재 후보가 비노출 실행을 지원하지 않으면 최종 목표는 미완료로 유지한다. 확정된 휴대폰·비노출 조건을 충족하는 실제 연결이 검증되기 전까지 미래의 성공·자동 배경 실행·모든 방의 즉시 갱신을 약속하지 않는다.
