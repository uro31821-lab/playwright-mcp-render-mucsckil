# JH Secure Live 안정화 규칙 불변 계약 — STAB-01 + STAB-03

기준: 2026-11-17, 플러그인 1.34.122의 사용자 확정 규칙 및 JH214 현재 운영본.
**새 비서·새 원장·새 카메라 동작을 만들지 않는다.** 기존 확정 규칙의 의미, 우선순위, 개인정보 보호, 인증·승인·중복 방지, 저장·삭제 정책은 수정하지 않는다.

## 변경 소유자
- 주관 비서관리비서: 기존 작업의 주담당·명시적 목적 보존, 협력 결과 인계.
- 에비서: 사용자가 확정한 규칙의 원문·버전·우선순위를 검증한다. 규칙 개정은 사용자의 새로운 명시 지시가 있어야 가능.
- 개발비서: 코드 최소 변경 및 신규 변화의 영향 범위 검사.
- 깃비서: 원본과 후보 비교·규칙 변경 차단·롤백·PASS 재사용.
- 준비비서: 동일 Tasks와 CURRENT 인계, 미검증 결과 기록.

## STAB-01: 기존 라우터의 입력을 보수적으로 정규화
- 실제 CLI의 `route` / `route.check_response`에서만 같은 `routeInput`을 사용한다. 라우터 원본 및 `workflow.plan`, Tasks, 사용자 선택, 앱 실행 경로는 **그대로 유지**.
- host가 동일한 현재 촬영 작업을 검증한 경우만 `photo`라는 단순 이미지 분류를 `camera` 주담당으로 해석한다. 단순히 사진이 존재한다는 이유로 전환하지 않는다.
- 현재 thread/source와 revision, 기존 활성 카비서, 사용자 명시적 촬영 시작, 저장 작업 없음, 미확정 외부 효과 없음, 지금 입력이 계속되는 촬영 목표라는 호스트 판단, 명시적 편집·새 목표·선택이 **없다는 사실**을 모두 확인해야 한다.
- 정보 하나라도 누락/불명확하거나 사용자가 편집·전환을 요청하면 **원래 입력을 그대로 보존**. `UNCERTAIN`을 성공으로 둔갑시키지 않는다.
- 카비서의 `참고사진 1~10장 → 주인공 마킹 → 분위기 → 설정 → 구도 3줄 → 사용자 자동촬영 → 에이밍` 순서는 수정 불가. 편비서는 명시적 편집 시에만 개입.
- 이 기능은 읽기/라우팅 제안만 한다. 셔터, 자동 사진 편집, Android 앱 설치, 개인기억 저장, 승인, 예약/결제/발송을 실행하지 않는다.

## STAB-03: 기존 협력 결과 검사 호출을 보존
- 새 결과 엔진을 만들지 않는다. 기존 `route.check_response` → `checkRouteResponse` → `checkFeatureResults`로 검사.
- `planned` 협력 항목은 각자 `featureResults` 응답을 돌려줘야 한다. 실제 결과/영수증/출처 없으면 `completed` 대신 `blocked` 또는 `not_used`와 **보이는 이유**를 반환해야 한다.
- `id, owner, sourceRef, threadId, taskId, conditionRevision, menuId`를 원 계획과 대조한다. 중복·다른 작업 결과·증빙 누락을 거절한다.
- 기존 `response.sections`와 사용자에게 보이는 링크·구간 검증도 유지한다. 사용자에게 보인 것과 외부에서 실제 수행·확정된 것의 차이를 구분한다.
- 코드 검사 PASS는 실제 호스트가 매 응답에서 검사를 호출했다는 E2E 증거가 아니다. 호출 누락이 있으면 호스트 연동 결함으로 별도 수정한다.

## 게이트/완료 증거
- G1: 기존 1.34.122 manifest의 기존 20개 defaultPrompt, 키워드 119개, `.app.json`, `.mcp.json`, 카비서·편비서·에비서 원본 정책을 byte-identical 유지. 허용 변경은 CLI 1파일의 국소 포트, 새 가드, 새 회귀 테스트, 위 정책 문서, manifest의 1.34.123 버전 및 지침 **추가 1항만**.
- G2: 최소 STAB-01 독립 30개, CLI 연결 10개, STAB-03 결과 검사 7개. 전역 확정 규칙 회귀와 실제 서비스 E2E는 별도 표기.
- G3: 실제 호스트가 신뢰 가능한 `conversationContext`를 공급하고 `route.check_response`를 실제 호출하는지 관찰. 누락 시 **연결 미검증**, 사용자에게 완료 보고 금지.
- G4/G5: 사용자 행동·다른 서비스 효과, Android 빌드/서명/재설치, Secure56 재승인은 시도하지 않는다. 변경 필요 시 별도 영향 검토.

## 재사용 PASS
JH214 원본 인증서·설치 APK 해시·Secure56·카비서 실사용 보고는 현재 변경 범위 밖이므로 유효한 기존 PASS로만 재사용한다. 실제 현재 재확인 없이 새 라이브 PASS로 표시하지 않는다.
