# JH 최초 신뢰 등록 — 계정 인증 입구·암호화 요청 장부 검증

## 이번 결과

기존 신뢰 기기 등록장부에 전달하기 전, 계정과 정확한 등록 요청을 검사하는 별도 서버 모듈을 작성했다. Google 공식 인증 라이브러리와 P-256 서명, 실제 파일형 SQLite를 사용한 격리 시험 31개가 통과했다.

이 코드는 아직 **기존 앱/신뢰 Registry에 통합하지 않은 추가 모듈**이다. 반환 코드는 `AUTHENTICATED_ENROLLMENT_NOT_APPLIED`이며 `trustCreated=false`, `sessionCreated=false`, `actionApproved=false`다. 주인님 실제 계정으로 로그인하거나 신뢰를 등록하지 않았다. 자동 재연결 활성화도 아니다.

## 기존 작업과 분리한 범위

이번에는 로컬 컨테이너 및 Python 실행 요청이 ClientError로 실패했다. 따라서 최신 앱 ZIP을 펼쳐 수정하거나 Android 전체 빌드 420개 검사를 재실행하지 않았다. 이전 420개 결과는 직전 보고서의 결과이며, 이번 새 서버 시험 31개와 합산하지 않는다.

대신 기존 공개 GitHub 저장소의 별도 검증 브랜치에서 새로 작성한 일반화된 모듈만 시험했다. 개인 앱 원본, 실제 계정 토큰, 기기 키, 기억/사진/건강 자료를 그 환경으로 보내지 않았다. 운영 브랜치와 서버에는 반영하지 않았다.

## 구현 내용

1. **계정 인증**: Google 서명, 발급자, 대상 앱, 유효기간 및 허용된 계정 고유 식별자(sub)를 확인한다. 이메일 주소만 같거나 요청에 confirmed=true가 들어갔다고 허용하지 않는다. Google 인증은 AI 제공자를 바꾸는 것이 아니다. 기존 ChatGPT/Drive 연결에서 인증 정보를 자동 공유받았다고 가정하지 않는다.
2. **정확한 등록 요청 연결**: 서버 주소, 기기 공개키, 기기 식별 해시, 도구목록, 1/7/30일 선택, 요청 식별값과 만료시각을 묶은 도전값을 사용한다. 계정 인증 토큰의 nonce와 기기 서명이 같은 요청에 연결되어야 한다.
3. **한 번만 인정**: 같은 요청을 재사용하거나 동시에 접수해도 한 번만 인증 완료된다. 인증 도중 취소/만료되면 늦은 성공으로 되살리지 않는다.
4. **암호화된 요청 장부**: AES-GCM, 외부에서 주입되는 키, SQLite 트랜잭션을 사용한다. 처리된 요청은 DB를 닫고 다시 열어도 사용 상태를 보존한다. 실제 로그인 토큰/개인 서명키는 저장하지 않는다.
5. **명확한 초기화/복구**: DB가 사라졌을 때 자동으로 빈 장부를 만들어 신뢰하지 않는다. 키 또는 운영 세대 식별값이 다르면 중단한다. 같은 세대의 과거 DB 전체 복원까지 자동 검출하는 기능은 아니며, 백업 복원 시 별도 세대 교체 정책이 필요하다.

Google 로그인 화면, OAuth 클라이언트 등록, 실제 소유자 설정, 기존 Android 동의 화면과의 요청 규격 결합은 남아 있다. 기기 서명만으로 사람의 직접 터치/생체인증을 증명한다고 주장하지 않는다. 현재 모듈은 Google 계정 검증 경로 후보이며 사용자 운영 계정 제공자를 임의 전환하지 않았다.

## 운영 저장소 확인 — 지금 발견한 적용 전 조건

Render의 기존 JH 서비스 조회 결과 실행 인스턴스 plan은 `free`였다. 같은 확인된 Render 작업공간의 Postgres 목록에는 인스턴스가 없었다. 다른 클라우드나 별도 외부 DB가 전혀 없다고 단정하는 결과는 아니다.

Render 공식 문서상 기본 파일시스템은 일시적이다. 재시작/재배포/무료 서비스 중단 후 파일과 로컬 SQLite를 계속 보존하려면 별도 영속 구성이 필요하다. 무료 웹 서비스에는 영속 디스크를 붙일 수 없다.

따라서 이번 파일형 DB 시험 통과를 현재 운영 서버의 영속 저장 성공으로 대신하지 않는다. 유료 디스크나 별도 비만료 DB의 선택/구성이 남아 있고, 비용이 드는 자원을 새로 만들거나 요금제를 변경하지 않았다. 영속 환경이 확인되기 전 장기 기기 신뢰를 운영에 켜지 않는다.

## 다음 통합 조건

- 정상 로컬 빌드 환경에서 이 추가 모듈을 최신 420개 검사 기준 앱/신뢰 Registry와 연결하고 종합 재검증.
- 실제 계정 인증 클라이언트와 사용자 허용 정책을 안전하게 구성. 현재 Google Drive 접근권한을 JH 신뢰 등록 권한으로 대체하지 않음.
- 처음 등록의 응답 유실 조회/정리와 Registry 반영 영수증을 연결. 이 모듈만으로 등록 완료를 표시하지 않음.
- 운영 영속 저장소, 키 보관, 백업 복원 및 해제 이력 정책 구성.
- 최종 통합본 한 번 설치 후 실제 사용자 기기에서 등록/재연결/취소/해제 확인.

기존 GPT-only 목표, Orchestrator/Router, Memoria Cloud v3와 첨부 직접 저장/ZIP 내부 한글 검색, 책툰·시킨대로 먹어 범위는 그대로다. 이번에 그 기능들을 추가 완료했다고 세지 않는다.

## 변경 상태

새 검증 브랜치의 소스/워크플로/이 기록만 추가했다. 운영 브랜치는 `aca64736870b07bc0b92dedf93447eeac9b7b8e4` 그대로임을 비교 시 확인했다. 휴대폰 조작/승인/설치, 운영 배포/재시작, 유료 서버 생성/요금 변경, API 키 조회, GPT 호출, Drive 업로드, Memoria 기록 변경은 수행하지 않았다. 실행한 검증 job은 종료 확인했다. 상시 모니터링은 설정하지 않았다.
