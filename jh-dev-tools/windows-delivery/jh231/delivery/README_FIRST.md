# JH231 저장 글 선택 수정 — 원래 PC에서 업데이트

JH 앱에서 같은 목록의 글을 구분해 선택하도록 수정한 버전입니다. 서버 수정은 별도 작업이며, 이 파일은 휴대폰 앱 업데이트만 수행합니다.

## 실행

1. JH230을 서명했던 원래 Windows PC에서 ZIP 전체를 짧은 로컬 폴더(예: `C:\JH231`)에 압축 해제합니다.
2. 원래 휴대폰 한 대만 USB로 연결하고, 휴대폰에서 USB 디버깅 연결을 허용합니다. 기존 JH 앱은 그대로 둡니다.
3. `실행.cmd`를 한 번 실행합니다. 새 빌드는 하지 않으며, 원래 PC의 기존 서명키로 서명한 뒤 기존 앱에 업데이트를 한 번 시도합니다.
4. 화면의 `RESULT_PATH`와 `BOOTSTRAP_RESULT_PATH`에서 이번 실행 결과를 확인합니다.

## 결과의 의미

- `PASS_UPDATE_INSTALLED_VERIFIED`: 업데이트 후 앱 ID·버전231·기존 인증서·설치 APK SHA256까지 확인했습니다.
- `ALREADY_INSTALLED_VERIFIED_NO_INSTALL`: 동일한 APK가 이미 설치되어 있어 추가 설치하지 않았습니다.
- `BLOCKED_NO_INSTALL`: 설치 전에 조건이 맞지 않아 중단했습니다. 결과 파일의 `REASON`을 확인합니다.
- `UPDATE_OUTCOME_UNCONFIRMED_NO_RETRY` 또는 `UNKNOWN...`: 결과가 확정되지 않았습니다. 실행을 반복하지 말고 이번 결과 파일로 다음 확인을 진행합니다.

인스타그램 저장 글을 실제로 여는 기능 시험은 이 업데이트에 포함되지 않습니다. 설치 확인 후 JH에서 이어서 검증합니다. 기존 앱을 삭제하거나 앱 데이터를 지우지 않습니다. 비밀번호·개인키는 이 파일에 넣거나 전송하지 않습니다. 기존 서명키를 찾지 못하면 새 키를 만들지 않고 중단합니다.

## 기존 자료 보존

각 실행에는 새로운 RUN_ID가 부여됩니다. 기존 RESULT와 서명된 APK는 덮어쓰지 않습니다. 서명된 APK가 이미 있으면 내용·인증서가 정확히 일치하는지 확인한 뒤 재사용합니다. 설치 시도 기록은 원래 PC의 JH 설치 기록 위치에 남겨 중복 실행을 막습니다. 결과 파일을 전달할 때는 이번 실행의 파일만 사용하세요.

## 필요한 기존 환경

Windows PowerShell 5.1, 원래 PC의 JDK/keytool, Android SDK의 adb/aapt/apksigner, 기존 JH 서명키 위치 기록이 필요합니다. 도구·키·인증 정보를 새로 내려받지 않습니다. 기존 Windows 전원/오류 점검 기준 이후 Kernel-Power 또는 Bugcheck가 있으면 중단합니다.
