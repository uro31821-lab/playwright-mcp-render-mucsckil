JH PowerShell 실행 전 오류 방지 체크리스트
규칙: JH-ZIP-RELEASE-POLICY-20261031

이 파일은 Windows APK 전달 ZIP에 포함할 체크리스트 템플릿입니다.
실행.cmd의 사전검사에서 아래 항목을 실제 검사하고 RESULT.txt에 기록하도록 실행기를 연결해야 합니다.
이 텍스트 파일 자체는 검사 코드가 아니며, 파일 포함만으로 자동 검사가 완료되지 않습니다.
상태는 PASS / FAIL / BLOCKED / NOT_RUN / UNKNOWN으로 구분하고 미확인 항목을 PASS로 기록하지 않습니다.

1. 압축 미해제
   전체 ZIP을 해제한 실제 전달 폴더인지, 필요한 파일이 함께 있는지 확인합니다.
   압축 폴더나 불완전한 임시 추출 상태에서 빌드·서명·설치를 시작하지 않습니다.

2. 스크립트 경로
   현재 작업 폴더가 아닌 실행기 위치를 기준으로 호출 대상 경로를 확인합니다.
   공백·한글 경로의 인수 인용과 스크립트 존재 여부를 확인합니다.

3. 인코딩
   대상 PowerShell의 BOM·한글·구문 처리와 실행.cmd의 ASCII/CRLF를 확인합니다.
   정적 검사 통과와 실제 Windows 구문·실행 확인을 구분합니다.

4. $Matches 변수 충돌
   $Matches 등 PowerShell 자동변수를 작업용 변수로 덮어쓰지 않습니다.
   기존 자동변수 검사와 함수 이름/기본 별칭 충돌 검사를 유지합니다.

5. 폴더 누락
   필요한 payload·도구·스크립트와 결과 저장 위치를 확인합니다.
   필수 입력이 없으면 해당 단계에서 중단하고 누락 항목을 기록합니다.

6. 경로 길이
   압축 해제 후 Windows의 실제 전체 경로를 확인합니다.
   현재 사용 도구가 지원하는 범위를 넘으면 작업 전에 중단합니다.

7. 해시 불일치
   현재 manifest·APK의 예상 SHA-256과 실제 값을 비교합니다.
   불일치하거나 확인하지 못한 결과를 MATCH로 기록하지 않습니다.

8. 중복 설치
   대상 기기·패키지·기존 설치 상태·실행 잠금·동일 작업 시도 기록을 확인합니다.
   같은 APK·기기·실행에서 업데이트 설치를 한 번만 시도합니다.
   실패·응답 불명확 시 자동 반복 설치나 앱 삭제로 전환하지 않습니다.

9. 기존 파일 보존과 현재 실행 결과
   기존 RESULT.txt와 signed/aligned APK를 덮어쓰거나 실패 정리에서 삭제하지 않습니다.
   정리는 같은 폴더의 잠금을 확보한 뒤 현재 실행이 새로 만든 출력에만 적용합니다.
   새 실행 ID와 실제 결과 경로를 확인하고 이전 성공 파일을 이번 결과로 재사용하지 않습니다.
   설치 실패에도 시도 횟수를 0 또는 1로 기록합니다.

10. 결과 저장과 전달 파일 계약
    단계·진단 로그 쓰기 실패와 별도로 RESULT.txt 저장을 시도합니다.
    주 위치가 불가능하면 새 fallback 폴더와 실제 저장 경로를 안내합니다.
    모든 저장이 실패하면 RESULT_WRITE_FAILED를 알리고 저장했다고 주장하지 않습니다.
    PowerShell 호출 뒤 결과가 불명확하면 UNKNOWN이며 기기 작업 미실행을 단정하지 않습니다.
    Windows APK ZIP은 고정 등록부의 검토된 프로필로 필수 파일·크기·SHA-256을 대조합니다.

필수 진행 순서
1) 현재 입력과 성공 기록 및 APK 해시가 일치하면 기존 빌드를 재사용합니다.
2) 원래 PC의 기존 인증서만 사용하며 새 인증서를 만들지 않습니다.
3) 기존 앱을 삭제하지 않고 업데이트를 한 번만 시도합니다.
4) 실제 설치 상태를 확인하고 성공·실패·차단·미실행을 RESULT.txt에 기록합니다.

검사 미구현·실패 항목이 있으면 관련 빌드·서명·설치 전에 중단합니다.
기존 성공 기록은 적용 조건이 같을 때만 재사용합니다.
개인키·인증 비밀번호·토큰을 이 파일이나 RESULT.txt에 기록하지 않습니다.

11. 패키지명/버전 검사 오류 재발 방지
   승인된 동일 APK 해시, 기존 인증서 및 SDK 35 aapt/이진 매니페스트 검증 영수증을 대조합니다.
   PC의 aapt 출력 형식 오류가 유효한 APK 업데이트를 잘못 차단하지 않도록 합니다.
   영수증 또는 APK가 일치하지 않으면 설치하지 않습니다.
