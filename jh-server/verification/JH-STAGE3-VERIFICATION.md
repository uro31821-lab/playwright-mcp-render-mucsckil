## 실제로 바뀐 연결

`verified-roundtrip-runtime.mjs`가 기존 생성 런타임의 `life_android_open_and_snapshot` 처리기 안에 선택적 경로를 연결한다. `return_to_origin=true`와 유효한 `workflow_id`가 있는 명시적 요청만 적용한다. 현재 대상은 카카오T 실행 후 원래 앱 복귀다. 새로운 MCP 도구, 공개 HTTP 경로, 로그인 권한, 별도 지속 작업 장부는 만들지 않는다.

첫 요청 하나 → 원래 앱 확인 → 기존 mk/waitJob로 카카오T 실행 → 실제 완료 보고 및 화면 재조회 확인 → 기존 복귀 명령 → 원래 앱 재조회 순서다. 테스트 코드가 각각의 후속 MCP 명령을 수동 호출하는 2차와 달리, 이번에는 기존 MCP 처리기가 연결된 실행기를 실제로 호출한다.

1. 운영 배포·APK 변경·사용자 휴대폰 조작은 모두 0회. 실제 Android OrchestratorLife 본체 통합/빌드 완료가 아니다.

5. 일반적인 다단계 업무 전체 완료, 검색 내용/스크롤 좌표 복원, Secure 자동 연장, 메모리아는 이번 범위가 아니다. 이미 사용자가 통과 확인한 앱 복귀·검색 유지 상태는 되돌리지 않는다.
