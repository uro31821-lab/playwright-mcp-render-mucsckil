# 제비서 독립 시험 — AutoJs6

**글 선택 → 선택 메뉴의 `⋯` → Gemini로 보내기 → Gemini 입력 확인 → 전송 1회**만 따로 시험하는 프로그램입니다. AutoJs6에서 실행합니다. 현재 JH 앱·서버·운영 명령에는 연결하지 않았습니다.

## 현재 단계

독립 실행 코드와 오프라인 회귀검사 후보입니다. **실제 휴대폰 시험을 통과한 완제품이 아닙니다.** 정확한 검사 결과·소스 기준·다음 행동은 [CHECKPOINT.md](CHECKPOINT.md)에 기록합니다. 설치·실기기 시험·JH 병합은 각각 별도 단계입니다.

## 휴대폰에서 실행할 파일

`dist/jebiseo-independent-test.js` 한 파일이 실행본입니다. AutoJs6 앱에서 이 스크립트를 가져옵니다. 본 저장소에는 AutoJs6 APK나 접근성 권한 자동 부여 기능을 넣지 않았습니다.

1. 공식 [AutoJs6](https://github.com/SuperMonster003/AutoJs6/releases/tag/v6.8.0) 실행 환경을 준비하고, Android가 요구하는 접근성 허용은 휴대폰에서 직접 완료합니다. 이 시험 파일은 기본 JavaScript/Rhino 환경용이며 MCP·Node.js·AI 플러그인을 설치할 필요가 없습니다. 공식 v6.8.0 배포를 확인했지만 해당 APK에서 이 스크립트를 실행하는 검증은 아직 하지 않았습니다.
2. 왼쪽에는 ChatGPT, 오른쪽에는 Gemini 네이티브 앱을 표시합니다. 분할 화면을 유지한 상태에서 AutoJs6의 떠 있는 스크립트 실행 버튼으로 시험 파일을 시작합니다. AutoJs6 편집기가 전체 화면을 차지한 상태에서는 분할 배치를 확인할 수 없어 중단됩니다.
3. 첫 실행은 **1. 읽기 전용 점검**을 선택합니다. 앱 창·입력란·대상 문장·선택 메뉴의 관찰 가능 여부를 확인합니다. 이 모드는 글 선택·메뉴 클릭·전송을 하지 않습니다.
4. 관찰 조건이 맞으면 2번(선택), 3번(메뉴 전달), 4번(전송) 중 시험 범위를 선택합니다. 기본 시험 문장을 읽고 시작하며, 각 실행에는 새 시험 ID를 부여합니다. `Gemini로 보내기` 메뉴 자체가 즉시 질의를 보낼 수도 있으므로 **3번도 외부 전달 동작**입니다.
5. 결과 창의 단계·상태·코드를 확인합니다. 볼륨 아래 버튼은 현재 시도를 중지합니다. 강제 종료나 미확인 전송 뒤에는 동일 동작을 자동 재실행하지 않습니다.

각 메뉴는 처음부터 실행하는 독립된 시험입니다. 3번으로 입력란에 글을 전달한 뒤 4번을 시험하려면, 이전 초안을 직접 확인·정리하고 새 빈 입력란에서 시작해야 합니다. 기존 초안이나 진행 중인 응답이 있으면 덮어쓰지 않고 중단합니다.

### 기본 시험 문장

아래 문장이 왼쪽 ChatGPT의 화면에 실제로 보여야 합니다.

> 제비서 독립시험: 이 문장을 받으면 확인이라고만 답해 주세요.

일상 대화 전체를 보내지 않으며, 화면 밖의 다른 글을 스크롤해서 찾지 않습니다. 원문이 여러 접근성 노드로 나뉘거나 선택 범위를 읽을 수 없으면 현재 후보는 `blocked`로 보고합니다. 화면별 보정은 실제 점검 결과를 근거로 추가합니다.

## 어떤 방식으로 동작하나요?

- 현재 활성 창 한 개에 의존하지 않고 접근성 서비스의 창 목록을 읽습니다. 같은 화면의 왼쪽 ChatGPT와 오른쪽 Gemini를 각각 식별합니다.
- Gemini를 여는 패키지 `com.google.android.apps.bard`와 현재 JH 원본에서 확인한 실제 화면 호스트 `com.google.android.googlequicksearchbox`를 구분합니다. Google 검색 창을 Gemini로 오인하지 않도록 Gemini 제목과 정확한 입력란 ID를 함께 확인합니다. 새 버전에서 값이 달라졌으면 관찰 없이 자동 완화하지 않습니다.
- 글을 길게 눌러 선택 모드로 들어간 뒤 Android의 선택 API로 정확한 범위를 지정합니다. 직접 드래그가 필요한 경우에는 실제 화면에서 확인한 손잡이 좌표·화면 크기의 보정값이 있어야 하며, 좌표를 추측하지 않습니다. 어떤 경로든 선택된 글을 다시 확인합니다.
- `android:id/overflow` 같은 실제 선택 툴바 요소와 그 상위 툴바를 확인합니다. ChatGPT 대화의 일반 `⋯` 버튼을 누르는 대상으로 삼지 않습니다.
- `⋯`를 누른 뒤 새 메뉴가 나타나는 것을 기다리고, 정확한 Gemini 항목을 다시 찾습니다. 팝업이 다른 창에 표시되면 창 소유 관계를 검사합니다.
- Gemini 입력란에 전달된 글이 일치해야 전송 버튼을 누릅니다. 입력란이 비워지고 새 메시지 또는 새 응답 생성 표시가 관찰돼야 전송 관찰 성공으로 기록합니다. 답변 내용의 정확도·완료까지 검증하는 기능은 아닙니다.

## 실행 결과와 중복 방지

| 상태 | 의미 |
| --- | --- |
| `probe_ok` | 읽기 전용 점검 조건 충족. 글 전달 성공이 아님 |
| `selection_verified` | 정확한 글 선택 범위 확인 |
| `handoff_verified` | Gemini의 미전송 입력 내용 일치 확인 |
| `submission_observed` | 한 번의 명시적 전송 후 새 제출 증거 관찰 |
| `blocked` | 필수 대상·선택 범위·배치 등을 확인하지 못해 정지 |
| `cancelled` | 사용자가 중지했으며, 코드가 기록한 단계 이후 자동 진행하지 않음 |
| `completion_unknown` | 메뉴 전달/전송 효과가 생겼을 수 있으나 완료를 확인하지 못함. 재전송 금지 |

AutoJs6의 앱 전용 저장소에 시험 ID·단계·결과만 기록합니다. 원문·전체 화면 트리·인증 정보는 결과 파일에 넣지 않습니다. 파일 잠금과 동기식 저장 후 메뉴/전송을 실행하여 중복 실행을 막습니다. **읽기 전용 점검은 미확인 기록을 자동 해제하지 않습니다.** 미확인 시도는 원래 결과를 검토하고 별도의 복구 결정을 하기 전까지 새 실행도 막습니다. 접근성 권한을 끄거나 앱 데이터를 지우는 것을 재시도 방법으로 권하지 않습니다.

## 설정과 개발 검사

기본값은 실행 파일에 들어 있습니다. 실제 화면 관찰로 보정이 필요할 때만 `profile.example.json`을 `profile.json`으로 복사하여 스크립트와 같은 폴더에 둡니다. 개인 문장·보정 파일은 Git에 포함하지 않습니다. 지원되는 보정 형식은 [CONTRACT.md](CONTRACT.md)의 `gestureSelection`을 참고합니다.

```sh
cd experiments/jebiseo-autojs6
npm run check
npm test
npm run build
node --check dist/jebiseo-independent-test.js
```

Node 18 이상, 추가 npm 의존성 없음. Node 검사는 제어 순서·창 구분·잘못된 메뉴·오래된 노드·중복 실행·미확인 결과 등을 가상 Android 객체로 재현합니다. **실제 Android 접근성·삼성 분할 화면·ChatGPT/Gemini 앱 동작의 검증을 대신하지 않습니다.** `build`는 동일 소스에서 한 파일 실행본을 만듭니다. `.github/workflows/jebiseo-autojs6-lab.yml`은 이 독립 모듈만 검사하며 기존 운영 검사를 바꾸지 않습니다.

## JH에 합칠 수 있는 조건

1. 주인님 실제 휴대폰에서 대상 문장 선택, `⋯`, Gemini 항목, 전달된 입력, 전송 관찰의 모든 단계가 통과해야 합니다.
2. 잘못된 창·메뉴 없음·키보드·분할 비율 변화·중지·미확인 결과를 같은 시험 회차에서 확인합니다. 재실행 중복이 없어야 합니다.
3. 성공한 실행 방법을 기존 JH 요청 ID·승인·취소·서명 영수증에 연결합니다. 이 시험의 로컬 결과 JSON을 JH 서명 영수증으로 간주하지 않습니다.
4. 당시 JH 기준본과 합친 조합의 회귀검사 후에만 병합합니다. 현재 draft PR과 시험 파일은 병합 승인이거나 배포 완료가 아닙니다.

기존 제비서 후보 PR #145의 `CLICK_GEMINI_MENU` 처리 내부에 실제 More→항목 선택을 넣는 방식을 우선 검토할 수 있습니다. 시험 결과에 따라 AutoJs6 호출 어댑터로 연결하거나 검증한 제어 방식을 기존 Android 실행기로 옮깁니다. 어느 쪽으로 합칠지는 실기기 결과로 결정합니다.
