# 제비서 독립 시험 0.3.4 — AutoJs6

**글 선택 → 선택 메뉴의 `⋯` → Gemini로 보내기 → Gemini 입력 확인 → 전송 1회**만 따로 시험하는 프로그램입니다. AutoJs6에서 실행합니다. 현재 JH 앱·서버·운영 명령에는 연결하지 않았습니다.

## 0.3.4 실제 저장 오류 수정

0.3.3의 실제 휴대폰·PC 결과에서 `SPLIT_PROBE_OK`, Gemini 입력 화면 식별, 한글 표시와 `PHONE_RESULT_RECEIVED`를 확인했습니다. 개인 결과파일 저장은 `DIR_FLAGS / java.lang.NoSuchFieldException`으로 실패했습니다. 문장 선택·메뉴·전달·전송은 아직 실행하지 않았습니다.

저장 코드가 조회하던 `OsConstants.O_DIRECTORY`는 Android 공개 API와 AOSP 클래스에 없는 필드입니다. 이전 Java 대역이 이 필드를 임의로 제공해 실제 오류를 놓쳤습니다. 해당 필드를 제거한 대역에서 이전 코드를 실행해 같은 실패를 재현했습니다. 새 코드는 공개 `O_RDONLY`로 연 파일 설명자를 `Os.fstat`·`StructStat.st_mode`·`OsConstants.S_ISDIR`로 확인한 뒤 디렉터리일 때만 동기화합니다. 검증 실패 시에도 연 설명자를 닫고, 최초 오류와 저널 차단을 보존합니다. Linux 상수 숫자나 비공개 API를 대신 사용하지 않습니다.

검사는 고정된 공식 Rhino/JVM뿐 아니라 CI에 설치된 실제 Android SDK의 공개 클래스·메서드·필드와도 대조합니다. SDK 검사는 서명 존재 확인이고 Android 파일시스템 실행 검증은 아닙니다. 근거: [OsConstants](https://developer.android.com/reference/android/system/OsConstants), [Os](https://developer.android.com/reference/android/system/Os), [StructStat](https://developer.android.com/reference/android/system/StructStat).

같은 화면에서 빈 입력란 여부가 확인되지 않아, 입력칸의 빈 문자열 여부와 안내 문구 상태를 참·거짓 진단으로만 추가합니다. 글·안내 문구 원문은 공개하지 않고, 안내 문구를 빈 초안으로 간주하거나 클릭 조건을 완화하지 않습니다.

이번에도 먼저 **1번 읽기**로 개인 저장까지 확인합니다. 공식 APK와 Windows 실행기는 0.3.3과 같고 설치된 동일 APK를 재사용합니다. 0.3.4의 실제 휴대폰 결과는 아직 `NOT_RUN`입니다.

## 0.3.3 실제 관찰에 따른 호환성 수정 — 당시 변경 기록

0.3.2 사용자 결과에서 Gemini의 정확한 설정 입력칸이 표시·활성·편집 가능 상태로 1개 관찰됐고, 제목 글자와 설명 이름은 각각 0개였습니다. 이번에는 그 관찰된 패키지와 전용 입력칸 ID가 유일하고 가려지지 않은 경우 제목 없이 화면을 확인합니다. 일반 검색창·유사 ID·임의 설정 ID·다른 앱·다중 입력칸은 이 경로를 사용할 수 없습니다. 기존 초안·선택 범위·미확인 전송의 재실행 차단은 유지합니다.

PC가 UTF-8 휴대폰 결과를 CP949로 읽어 한글이 손상될 수 있던 경계에 ADB 전용 UTF-8 디코더를 지정했습니다. 실제 Windows PowerShell 5.1과 CMD 회귀가 이전 손상 재현, 한글 JSON 수신·파일 저장·표시를 확인합니다.

당시 개인 저장은 `DIR_OPEN / OTHER`에서 실패한 관찰까지만 확정이었습니다. JavaScript 엔진이 Android Os 클래스 전체를 조사하는 경로 대신 공개 `open(String,int,int)`, `fsync(FileDescriptor)`, `close(FileDescriptor)`를 정확히 조회해 호출하도록 보완했습니다. 그러나 필드 조회에 Android에서 제공하지 않는 `O_DIRECTORY`가 남아 있었습니다. 고정된 공식 Rhino JAR의 JVM 검사도 이 필드를 제공하는 대역으로 실행돼 누락을 찾지 못했습니다. 이 결함과 후속 실제 관찰은 위 0.3.4 수정에서 다룹니다.

다음 실제 기기 확인은 **1번 읽기**입니다. 코드·CI 검증과 실제 폰의 수정 후 성공은 구분합니다. 공식 APK는 그대로이며 설치된 동일 APK를 재사용합니다.


## 0.3.2 읽기 진단 보강

0.3.1 사용자 시험에서 시작·분할 창 읽기·PC 결과 수신까지 진행된 것을 확인했습니다. Gemini 화면 식별은 `GEMINI_SURFACE_UNVERIFIED`로 중단됐고 개인 결과파일 저장 확인 경고가 발생했습니다. 공개 PC 결과 전달과 개인 저장 실패를 구분합니다.

이번 버전은 실제 Gemini 제목 일치 수와 입력칸 구조 정보(최대 8개), 개인 결과파일 저장의 실패 단계를 기록합니다. 대화·입력 내용이나 원문 예외 메시지는 새 진단에 포함하지 않습니다. 화면 식별 조건·클릭 조건은 유지하며, 관찰된 새로운 ID를 자동 승인하지 않습니다. 파일·디렉터리 sync와 저널 실패 차단을 유지하고 첫 저장 오류를 보존합니다. PC 결과 끝부분에 핵심 진단을 다시 표시합니다.

이번 전달 목적은 1번 읽기 시험으로 실제 기기의 불일치 원인을 확인하는 것입니다. Gemini 식별과 개인 저장 문제의 해결 또는 전체 전송 성공을 주장하지 않습니다. 기존 APK와 Windows 실행기를 재사용합니다.

## 0.3.1 시작 오류 수정

AutoJs6 6.8.0에 없는 `files.getParent()` 호출을 제거하고, 공식 런타임도 사용하는 `java.io.File.getParent()`로 실행 파일의 상위 폴더를 확인합니다. 테스트 대역에서도 미지원 API를 제거했습니다. 유효한 USB 실행 요청의 결과 통로를 개인 저장소·잠금 초기화보다 먼저 준비해, 해당 시작 단계 오류가 PC의 같은 실행 ID로 돌아오게 했습니다. 중복 엔진은 선행 실행의 결과를 덮어쓰지 않습니다.

공식 AutoJs6 APK, Windows 실행기, 권한 안내, 저널·전송 제한은 유지합니다. 이미 설치된 동일 APK를 재사용하며 파일만 갱신합니다. 실제 사용자 기기의 수정 후 화면 읽기는 별도 확인이 필요합니다.


## 현재 단계

독립 실행 코드와 오프라인 회귀검사 후보입니다. **실제 휴대폰 시험을 통과한 완제품이 아닙니다.** 정확한 검사 결과·소스 기준·다음 행동은 [CHECKPOINT.md](CHECKPOINT.md)에 기록합니다. 설치·실기기 시험·JH 병합은 각각 별도 단계입니다.

## Windows에서 압축 해제 후 실행

공식 AutoJs6 v6.8.0 원본 APK, Windows ADB와 DLL, 단일 시험 파일을 함께 묶는 `windows/` 실행기가 추가되었습니다. 사용자는 ZIP을 모두 풀고 USB로 휴대폰을 연결한 다음 `실행.cmd`를 엽니다. 수동 스크립트 가져오기 없이 앱 동일성 검사, 필요 시 1회 설치, 권한 설정 안내, 시험 선택, 실제 폰 요약 결과 회수까지 이어집니다.

첫 선택은 Enter만 누르면 읽기 전용 `probe`입니다. 휴대폰의 USB 연결 신뢰, 접근성·파일·다른 앱 위 표시 허용과 왼쪽 ChatGPT/오른쪽 Gemini 배치는 사용자가 직접 준비합니다. Android 권한을 강제로 부여하거나 분할화면 유지가 검증되었다고 가정하지 않습니다. 결과는 PC `RESULT.txt`/`RESULT.json`에 남깁니다. 파일 무결성과 모의 Windows 검사를 통과해도 실제 폰 시험 성공과는 구분합니다.

`launch-request.json`은 정확히 한 시험과 현재 PC 실행 ID만 전달합니다. 외부 실행 ID는 폰의 중복 방지 journal ID에 그대로 연결됩니다. USB 모드는 고정된 내장 profile만 사용합니다. `RESULT_PHONE.json`은 같은 ID가 있는 제한된 결과 요약만 공개 시험 폴더에 저장합니다. 기존 비공개 journal·대화 원문·초안은 내보내지 않습니다.

## 수동 실행 경로 — 개발용

`dist/jebiseo-independent-test.js` 한 파일이 실행본입니다. Windows 묶음에는 원본 APK를 포함하지만 소스 Git에는 바이너리를 저장하지 않습니다. 아래는 PC 실행기를 사용하지 않는 개발용 수동 경로입니다.

짧은 휴대폰용 순서는 [PHONE_TEST_KO.md](PHONE_TEST_KO.md)에 있습니다. 이번 버전은 **메뉴에 실제로 붙은 이름 읽기**, **`⋯`만 열고 Gemini 항목 확인**, **한글 결과와 복사**, **최근 결과 다시 보기**를 추가했습니다.

1. 공식 [AutoJs6](https://github.com/SuperMonster003/AutoJs6/releases/tag/v6.8.0) 실행 환경을 준비하고, Android가 요구하는 접근성 허용은 휴대폰에서 직접 완료합니다. 이 시험 파일은 기본 JavaScript/Rhino 환경용이며 MCP·Node.js·AI 플러그인을 설치할 필요가 없습니다. 0.3.3의 읽기 전용 시험은 사용자 기기에서 확인했고, 현재 0.3.4와 문장 선택 이후 동작은 별도 확인이 필요합니다.
2. 왼쪽에는 ChatGPT, 오른쪽에는 Gemini 네이티브 앱을 표시합니다. 분할 화면을 유지한 상태에서 AutoJs6의 떠 있는 스크립트 실행 버튼으로 시험 파일을 시작합니다. AutoJs6 편집기가 전체 화면을 차지한 상태에서는 분할 배치를 확인할 수 없어 중단됩니다.
3. 첫 실행은 **1. 화면·메뉴 읽기**를 선택합니다. 기본 10초 뒤 현재 화면을 한 번 읽습니다. 메뉴를 직접 열어 관찰하고 싶다면 이 준비 시간 동안 열어 둡니다. 이 모드는 글 선택·메뉴 클릭·전송을 하지 않습니다. 열린 선택 도구모음의 실제 메뉴 이름·설명은 최대 16개까지 결과에 표시됩니다. 관찰만 된 낯선 항목을 자동 클릭 대상으로 추가하지 않습니다.
4. 관찰 조건이 맞으면 2번(선택), 3번(`⋯` 열기·Gemini 항목 확인), 4번(전달), 5번(전송) 중 필요한 범위를 선택합니다. **3번은 Gemini 항목을 누르지 않습니다.** `Gemini로 보내기` 메뉴 자체가 즉시 질의를 보낼 수도 있으므로 **4번은 외부 전달 동작**입니다. 4·5번은 Gemini 입력란이 비어 있고 응답 생성이 끝난 상태에서 시작합니다.
5. 한글 결과 창에서 확인한 항목·막힌 단계·코드를 읽고, 다음 화면의 **결과 복사**를 눌러 이 대화에 붙여넣습니다. 6번(최근 결과 보기·복사)은 접근성 권한이나 화면 조회 없이 저장된 결과를 엽니다. 볼륨 아래 중지가 등록되지 않는 기기는 안내에 따라 AutoJs6 중지 버튼을 사용합니다. 강제 종료나 미확인 전송 뒤에는 동일 동작을 자동 재실행하지 않습니다.

**2~5번은 각각 문장 선택 단계부터 시작하며, 앞선 시험의 다음 단계만 이어 실행하는 버튼이 아닙니다.** 한 시험의 결과를 확인한 뒤 필요한 다음 시험을 고릅니다. 4번으로 입력란에 글을 전달한 뒤 5번을 시험하려면, 이전 결과·초안을 직접 확인·정리하고 빈 입력란에서 시작해야 합니다. 미확인 전송 기록이 있으면 새 동작 시험은 계속 차단됩니다. 조회만으로 차단을 해제하지 않습니다.

### 기본 시험 문장

아래 문장이 왼쪽 ChatGPT의 **답변 영역에 한 번만** 보여야 합니다. 입력창에 붙여 넣은 글은 선택 대상으로 사용하지 않습니다.

> 제비서 독립시험: 이 문장을 받으면 확인이라고만 답해 주세요.

일상 대화 전체를 보내지 않으며, 화면 밖의 다른 글을 스크롤해서 찾지 않습니다. 원문이 여러 접근성 노드로 나뉘거나 선택 범위를 읽을 수 없으면 현재 후보는 `blocked`로 보고합니다. 화면별 보정은 실제 점검 결과를 근거로 추가합니다.

## 어떤 방식으로 동작하나요?

- 현재 활성 창 한 개에 의존하지 않고 접근성 서비스의 창 목록을 읽습니다. 같은 화면의 왼쪽 ChatGPT와 오른쪽 Gemini를 각각 식별합니다.
- Gemini를 여는 패키지 `com.google.android.apps.bard`와 현재 JH 원본에서 확인한 실제 화면 호스트 `com.google.android.googlequicksearchbox`를 구분합니다. Gemini 제목과 정확한 입력란 ID를 함께 확인하거나, 실제 관찰된 전용 입력란의 유일성·창 소속·가림 여부를 확인합니다. 새 버전에서 값이 달라졌으면 관찰 없이 자동 완화하지 않습니다.
- 글을 길게 눌러 선택 모드로 들어간 뒤 Android의 선택 API로 정확한 범위를 지정합니다. 직접 드래그가 필요한 경우에는 실제 화면에서 확인한 손잡이 좌표·화면 크기의 보정값이 있어야 하며, 좌표를 추측하지 않습니다. 어떤 경로든 선택된 글을 다시 확인합니다.
- `android:id/overflow` 같은 실제 선택 툴바 요소와 그 상위 툴바를 확인합니다. ChatGPT 대화의 일반 `⋯` 버튼을 누르는 대상으로 삼지 않습니다.
- `⋯`를 누른 뒤 새 메뉴가 나타나는 것을 기다리고, 정확한 Gemini 항목을 다시 찾습니다. 팝업이 다른 창에 표시되면 창 소유 관계를 검사합니다.
- Gemini 입력란에 전달된 글이 일치해야 전송 버튼을 누릅니다. 입력란이 비워지고 새 메시지 또는 새 응답 생성 표시가 관찰돼야 전송 관찰 성공으로 기록합니다. 답변 내용의 정확도·완료까지 검증하는 기능은 아닙니다.

## 실행 결과와 중복 방지

| 상태 | 의미 |
| --- | --- |
| `probe_ok` | 읽기 전용 점검 조건 충족. 글 전달 성공이 아님 |
| `selection_verified` | 정확한 글 선택 범위 확인 |
| `menu_verified` | `⋯`를 열고 소속이 확인된 Gemini 메뉴 항목을 읽음. 해당 항목은 누르지 않음 |
| `handoff_verified` | Gemini의 미전송 입력 내용 일치 확인 |
| `submission_observed` | 한 번의 명시적 전송 후 새 제출 증거 관찰 |
| `blocked` | 필수 대상·선택 범위·배치 등을 확인하지 못해 정지 |
| `cancelled` | 사용자가 중지했으며, 코드가 기록한 단계 이후 자동 진행하지 않음 |
| `completion_unknown` | 메뉴 전달/전송 효과가 생겼을 수 있으나 완료를 확인하지 못함. 재전송 금지 |

AutoJs6의 앱 전용 저장소에 시험 ID·단계·결과와 범위가 제한된 메뉴 이름·설명을 기록합니다. 대화 원문·초안 본문·전체 화면 트리·인증 정보는 결과 파일에 넣지 않습니다. 복사용 보고서는 허용 필드만 남긴 `jebiseo.autojs6.public-report.v1` 형식이며 원본 실행 결과와 구분합니다. 파일 잠금과 동기식 저장 후 메뉴/전송을 실행하여 중복 실행을 막습니다. **읽기 전용 점검은 미확인 기록을 자동 해제하지 않습니다.** 미확인 시도는 원래 결과를 검토하고 별도의 복구 결정을 하기 전까지 새 실행도 막습니다. 차단 결과에는 원래 미확인 시도의 ID·단계·상태를 함께 표시합니다. 접근성 권한을 끄거나 앱 데이터를 지우는 것을 재시도 방법으로 권하지 않습니다.

## 설정과 개발 검사

기본값은 실행 파일에 들어 있습니다. 실제 화면 관찰로 보정이 필요할 때만 `profile.example.json`을 `profile.json`으로 복사하여 스크립트와 같은 폴더에 둡니다. 개인 문장·보정 파일은 Git에 포함하지 않습니다. 지원되는 보정 형식은 [CONTRACT.md](CONTRACT.md)의 `gestureSelection`을 참고합니다.

```sh
cd experiments/jebiseo-autojs6
npm run check
npm test
npm run build
node --check dist/jebiseo-independent-test.js
```

Node 18 이상, 추가 npm 의존성 없음. Node 검사는 제어 순서·창 구분·잘못된 메뉴·오래된 노드·중복 실행·미확인 결과 등을 가상 Android 객체로 재현합니다. **실제 Android 접근성·삼성 분할 화면·ChatGPT/Gemini 앱 동작의 검증을 대신하지 않습니다.** `build`는 동일 소스에서 한 파일 실행본을 만듭니다. `.github/workflows/jebiseo-autojs6-lab.yml`은 이 독립 모듈만 검사하며 기존 운영 검사를 바꾸지 않습니다.

## JH에 합칠 수 있는 조건

1. 주인님 실제 휴대폰에서 대상 문장 선택, `⋯`, Gemini 항목, 전달된 입력, 전송 관찰의 모든 단계가 통과해야 합니다.
2. 잘못된 창·메뉴 없음·키보드·분할 비율 변화·중지·미확인 결과를 같은 시험 회차에서 확인합니다. 재실행 중복이 없어야 합니다.
3. 성공한 실행 방법을 기존 JH 요청 ID·승인·취소·서명 영수증에 연결합니다. 이 시험의 로컬 결과 JSON을 JH 서명 영수증으로 간주하지 않습니다.
4. 당시 JH 기준본과 합친 조합의 회귀검사 후에만 병합합니다. 현재 draft PR과 시험 파일은 병합 승인이거나 배포 완료가 아닙니다.

기존 제비서 후보 PR #145의 `CLICK_GEMINI_MENU` 처리 내부에 실제 More→항목 선택을 넣는 방식을 우선 검토할 수 있습니다. 시험 결과에 따라 AutoJs6 호출 어댑터로 연결하거나 검증한 제어 방식을 기존 Android 실행기로 옮깁니다. 어느 쪽으로 합칠지는 실기기 결과로 결정합니다.
