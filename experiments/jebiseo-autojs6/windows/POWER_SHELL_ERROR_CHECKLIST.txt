Windows 실행 전·결과 확인 기준

1. 압축 해제: ZIP 안에서 바로 실행하지 않고 전체 폴더를 추출합니다.
2. 경로: 실행기는 자기 폴더의 절대 경로만 사용합니다. 공백·한글 경로를 따옴표로 처리합니다.
3. 인코딩: CMD는 ASCII/CRLF, PowerShell은 Windows PowerShell 5.1이 읽을 수 있는 UTF-8 BOM입니다.
4. 변수: 자동 변수 HOME/Matches와 공용 별칭을 작업 변수로 덮어쓰지 않습니다.
5. 파일·출력: 모든 필수 파일과 해시를 검사하고 현재 실행의 결과 경로를 기록합니다.
6. 경로 길이: 긴 경로는 변경 작업 전 차단합니다. C:\JebiseoLab 같은 짧은 경로를 권합니다.
7. 동일성: 공식 APK SHA-256, 스크립트, ADB/DLL 등 입력을 고정 목록과 대조합니다.
8. 중복 설치: 기기와 APK별 지속 시도 기록을 설치 전에 남기고 최대 한 번만 시도합니다.

기존 앱·이전 RESULT를 보존합니다. 앱 삭제, 서명키 생성, 임의 다운그레이드는 하지 않습니다.
Android 권한은 공식 설정 화면에서 사용자가 직접 허용합니다.
여러 USB 기기가 있거나 연결이 승인되지 않으면 임의 기기를 선택하지 않습니다.
원본 APK의 설치 결과는 패키지·버전·설치 파일 해시를 다시 읽어 확인합니다.
새 실행 ID와 일치하는 폰 결과만 현재 RESULT로 가져옵니다.
Activity 시작 성공과 휴대폰 시험 성공을 구분합니다.
결과 파일을 쓰지 못하면 별도 경로를 시도하고 실제 RESULT_PATH를 표시합니다.
unknown/blocked 결과에서 전달·전송을 자동 반복하지 않습니다.

개발 검증 범위
Node 오프라인 시험: 상태 제어, 메뉴 구분, 선택 확인, 중복 방지, 요약 내보내기.
Windows CI: PowerShell 5.1과 CMD에서 합성 ADB/임시 파일로 정상·오류 경로 검사.
공식 바이너리: 출처·크기·해시·APK 서명/패키지 검증.
위 검증은 사용자 PC의 실제 실행이나 휴대폰 시험 완료를 뜻하지 않습니다.
