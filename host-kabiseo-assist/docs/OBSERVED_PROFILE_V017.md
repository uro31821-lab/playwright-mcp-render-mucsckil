## 실제로 확인한 차이
인증된 Render 연결에서 서비스 설정, live 배포, 해당 배포의 시작 로그를 읽었습니다. 실제 배포 commit은 `0663e0c3b434f300803e5cf272609032a5e519d3`, 시작 경로는 `cd jh-server && npm start` → `published-host-router.mjs`입니다. 자동 배포는 꺼져 있습니다.

로그에는 Stage26 완료응답, Stage40/41 진단, Stage44 명령 초점, Mobile13 명령진단이 활성화됐다는 명시적 기록이 있습니다. v0.16의 최소 프로필은 이 다섯 항목이 미설정이어서 그대로는 일치하지 않았습니다. 전체 환경변수/비밀값을 읽은 것은 아니며, 양성 활성화 기록과 해당 소스에 정의된 설정만 연결했습니다.

별도로 운영 빌드 로그는 Node v26.13.0, 기존 검증 환경은 Node v22.23.4입니다. **운영 버전을 내리거나 차이를 무시하지 않습니다.** 이번에는 기존 캐시의 검증 환경을 재사용했으며 Node26 바이너리는 받거나 실행하지 않았습니다.

## 실제 적용과 시험
기존 생성기 원본을 수정하지 않고 별도 사본의 세 파일에 정확한 프로필만 적용하는 어댑터를 추가했습니다. 각 치환의 유일성과 전체 원문 역변환 일치를 검사합니다. 부모 5,010파일을 보존한 5,015파일 시작 후보를 구성했습니다.

운영 commit에서 같은 설정으로 생성한 원본 runtime SHA256은 `06b090d885be863723d0a8d3a74605ef15bd6f08595e8b4e82fb3a79b7c3986f`로 운영 시작 로그와 정확히 일치했습니다. 이는 원본 생성 코드의 바이트 일치이며, Node26 실행 의미·전체 환경·실제 소유자 저장소·휴대폰 성공의 증거가 아닙니다.

GitHub run42221499237/job127904401182, head `7fdb95dee91ee4861ad22c1ff1cfbed7a9b2d6fc`, attempt1은 completed/success입니다. 새 설정 검증 11묶음(그 안의 잘못된 프로필12개 거부 포함), 이전 최소프로필 검증12묶음(잘못된 환경23개 포함)을 통과했습니다. 중첩 수를 합산하지 않습니다.

실제 원래 시작 함수는 시험용 환경에서 기존 `STORAGE_SECRET_PAIR_REQUIRED`까지 진행해 차단됐습니다. enabled/disabled 시험은 합성 환경에서 실제 생성 runtime을 import했으며 listener를 열지 않았습니다. 실제 소유자 저장소까지 포함한 전체 시작 성공은 아닙니다.

첫 run42221262953은 오래된 검토 브랜치와 운영 브랜치의 기존 차이를 동일 원본으로 간주한 비교 때문에 시험 전에 실패했습니다. 보호 파일을 덮어쓰거나 제외하지 않고, 검토본은 마지막 검증 commit6016과 전체 jh-server 동일성 검사, 운영본은 실제 배포 commit0663의 원본 보존 검사로 분리했습니다. 생성은 운영본만 사용하고 운영 로그의 runtime 해시도 필수 대조합니다.
