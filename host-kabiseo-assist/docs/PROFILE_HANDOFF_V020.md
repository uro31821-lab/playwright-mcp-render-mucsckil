# 카비서 v0.20 — 수집 자료·검토·현지 승인·프로필 조회 연결 후보

2026-11-06. 사용자 계속 요청을 이어 받아 기존 v0.19 검사기를 사용하는 `CameraProfileHandoff`를 구현했습니다. 이번 변경은 저장소 tools 아래의 JVM 연결 후보이며, 실제 휴대폰 앱/서버에 편입하지 않았습니다.

## 이번 실제 구현
승인된 현지 수집기가 제공해야 하는 메타데이터 영수증을 받아 검토하고, 검토한 바로 그 자료에 대한 한 번의 현지 승인을 확인한 뒤 메모리 안에 한시적인 프로필을 유지합니다. 사용 흐름은 COLLECTING → REVIEW_READY → COMMITTING → ENROLLED_LOCAL_LEASE → CLOSED입니다.

- 기기·명령·세션·앱·버전·서명·폴더블 화면 구성을 같은 묶음으로 확인합니다.
- 표본은 최대32개, 수집 직후 확인은 기존350ms 기준, 세션은 최대5분으로 제한합니다. 촬영창 두 번 열림과 대화/사진확인창의 대조자료 요구는 기존 검사기를 재사용합니다.
- 자료·화면구분·열림/수집 ID·시각·노드 범위/플래그·선택한 기준점까지 digest에 포함하고 검토 후 추가 수집은 허용하지 않습니다. 다른 인스턴스의 티켓이나 예전 자료의 승인은 거부합니다.
- 현지 승인 소비가 실패/예외/미확정이면 자동 재시도하지 않고 닫습니다. 처리 중 취소·만료도 결과로 덮어쓰지 않습니다.
- 매 조회 시 현재 전체 식별값과 승인 유효성을 다시 확인합니다. 취소/다음 동작에서 확인된 만료/프로세스 종료 후에는 프로필을 재사용하지 않습니다. 반환된 Profile을 캐시하면 안 됩니다. `status()`는 권한을 주지 않는 내부 상태 스냅샷이며 실제 사용 허가는 항상 `resolve()`로 재확인해야 합니다.
- 기존 CameraSurfacePolicy와 연결한 가상 시험에서 허용 결과도 읽기 전용이며, 제스처/픽셀/카메라 설정 변경 권한은 없습니다.

## 인증 구현과 시험용 가정을 구분
Host의 기본 구현은 모두 거부합니다. Host는 실제 원래 인증·현지 관찰 label·현재 화면 ID·일회성 phone-local approval을 검증해야 합니다. 이 컨트롤러가 새 인증체계를 구현하거나 단순 boolean을 실제 기기 증거로 바꾸는 것은 아닙니다. 테스트 Host의 true 응답은 가상 사례만 검증합니다.

현재 Android helper의 `Profiles { _,_,_ -> null }`는 변경하지 않았습니다. 프로필이 실제 등록됐다고 표현하지 않습니다. 저장소 새 코드가 Host 승인을 통과한 뒤 만드는 attested Profile은 그 신뢰 계약 아래의 세션 한정 결과이며, 실기기 관찰·승인 자체가 없으면 실제 환경에 만들 수 없습니다.
