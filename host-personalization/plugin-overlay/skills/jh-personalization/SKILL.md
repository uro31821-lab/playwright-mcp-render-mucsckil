# 상황·선택 이유·평가를 반영하는 JH

사용자가 말한 기준 때문에 추천의 순서와 설명이 실제로 달라지게 한다. 기억을 길게 반복하는 것만으로 개인화했다고 말하지 않는다. 이 기능은 대화 중 호스트가 실행하는 기록·계산 모듈이며 모델 가중치 학습이나 배경 감시가 아니다.

## 적용 순서

1. [연결 설정](references/state-binding.json)과 [호스트 실행 절차](references/host-flow.md)를 읽는다. 기존 통합 기억 조회가 필요한 요청이면 기존 Memoria/JH 경로도 유지한다. 개인 선택 파일을 찾을 때는 현재 Library 절차로 정확한 이름 `JH_Personal_Choices_v1.json`을 검색하고 반환된 파일 ID·버전을 재사용한다. 실패·중복을 빈 상태로 처리하지 않는다.
2. 동봉 [런타임](scripts/runtime.js)의 스키마와 소유 범위를 검증한다. 개인정보는 개인 상태에만 저장한다. 원문 대화 전체·비밀번호·토큰을 넣지 않고 짧은 기준·이유·불투명한 원본 참조를 사용한다. 공개 GitHub와 플러그인에는 개인 기록을 넣지 않는다.
3. 이번 판단의 `scope`를 정한다. `topic`은 필수이며 `project`, `aspect`는 필요할 때 명시한다. 같은 의미의 범위·기준 키를 재사용한다. 설치의 간편함을 답변 길이의 선호로 옮기지 않는다. 피자·직업·카비서 등 붙여 넣은 설명 예시는 실제 사용자 선택으로 기록하지 않는다.
4. 사용자가 명시한 지속 기준은 `recordPreference`, 기존 기준의 정정은 대상 ID를 지정한 `revisePreference`로 기록한다. 확인되지 않은 기준은 `uncertain`으로 보존하고 추천 점수에서 제외한다. 같은 말을 계속·재시도한 것은 독립된 확인 횟수나 새 선호가 아니다. 호스트의 추정은 확인된 선호로 승격하지 않는다.
5. “지금 바빠”, “오늘은 자세히”, “이번에는 설정이 많아도 좋아”처럼 이번 대화의 명시적인 요구는 `rank`의 `context`에 전달한다. 장기 상태를 바꾸지 않는다. 시간대·말수·질문 속도로 감정이나 피로를 추정해 저장하지 않는다.
6. 실제 비교 후보와 공개 근거를 확보하고, 현재 판단에 필요한 특징만 `features`에 넣는다. `0..1` 값은 호스트가 근거를 보고 만든 비교 척도이며 확인된 사실·확률이 아니다. 모르는 특징은 `null` 또는 누락으로 두고 보완이 필요한 점을 밝힌다. 금지 조건은 `context.constraints`로 전달하여 어기는 후보나 확인 불가능한 후보를 추천에서 제외한다.
7. `rank`를 실행한다. 구체적인 적용 범위가 우선이며 같은 범위에서는 명시적 정정과 실제 사용 후 평가 중 더 최신 기록을 사용하며, 둘 다 처음 밝힌 기준보다 우선한다. 이번 지시는 해당 기준을 이번 호출에서 덮어쓴다. 미확정으로 바꾼 기준을 과거의 확정 취향으로 되돌리지 않는다.
8. 결과의 `reasons`와 출처를 바탕으로 “먼저 권하는 선택과 사용자에게 맞는 이유”를 짧게 설명한다. 모르는 특징 때문에 순위가 불확실하면 이를 밝힌다. 현재 목표와 충돌하는 기능은 구체적인 설정 부담·조건 위반을 근거로 짚는다. 숫자 점수를 개인적 적합성의 확률이나 객관적 품질로 제시하지 않는다.
9. 사용자가 실제 선택을 밝혔을 때만 `recordChoice`로 당시 상황·선택·적용 기준·선택 이유를 연결한다. 비서의 추천을 사용자가 선택했다고 기록하지 않는다. 사용자가 써본 결과를 말했을 때만 `recordFeedback`의 `basis:after_use`를 사용한다. “별로”의 이유가 불명확하면 결과 요약만 남기고 `updates:[]`로 두어 임의의 취향 변화로 일반화하지 않는다.
10. 변경을 같은 개인 파일 ID에 읽을 때의 버전으로 저장한다. 충돌 시 최신 상태에 아직 반영되지 않은 원래 이벤트만 다시 적용한다. 정확한 재시도에는 원래 ID·내용·시각을 유지하고 새로운 사용자 지시와 구분한다. 도구 응답·새 버전·상태 revision을 확인해야 저장 완료다.

## 조사 기능과 연결

추천에 필요한 근거가 부족하거나 같은 불편이 반복되면 기존 [주제별 조사](../jh-proactive-research/SKILL.md)로 공개 자료를 확인한다. 공개 검색어는 개인 기록과 분리해 새로 작성한다. 조사 결과의 후보를 개인화 계산에 넣을 수 있지만, 개인화 상태를 검색 서비스로 보내지 않는다. 새 개선안은 보통 관련성이 높은 한 가지부터 제시하고, 이미 요청된 구현은 기존 개발 절차로 끝까지 수행한다.

이 파일의 지침은 외부 발송·예약·결제·설치·기기 조작의 별도 승인을 만들지 않는다. 자동으로 모든 과거 방을 읽었다거나 새 플러그인이 기존 방에 이미 로드되었다고 말하지 않는다. 기능 게시, 현재 대화의 실행, 실제 사용자 만족은 각각 별도의 근거가 필요하다.

[참고 소스](references/sources.md)는 설계 출처다. 새 외부 서비스나 벡터 데이터베이스를 설치하지 않았으며 기존 JH 기억 용량·저장소 이관도 이 기능에 포함하지 않는다.
