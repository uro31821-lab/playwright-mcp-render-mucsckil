# JH Pattern Guidance 1.0.0

반복되는 **미해결 필요**를 찾고, 현재 목표·최신 기준·원문 출처·기존 사용 결과를 함께 검토하는 호스트 모듈입니다. v0.1의 독립 초안을 검증하고 고친 구현입니다. 새 모델, 벡터 DB, 외부 패키지, 자동 기기 조작은 없습니다. Node.js 22 이상을 사용합니다.

## 사용자에게 달라지는 부분
같은 작업의 계속/상태 조회는 기억을 늘리지 않습니다. 정정도 독립 작업별로 집계합니다. 성공 결과가 확인된 문제는 미해결 집계에서 제외합니다. 보류·거절·해결한 주제는 일반 질문만으로 다시 활성화하지 않습니다. 추정은 확정된 성향으로 바꾸지 않습니다.

최근 30일의 독립된 미해결 문제 2건, 정정 2건, 질문 3건 또는 명시적 조사 요청 1건을 판단 신호로 삼습니다. 이 수치는 초기 제품 규칙이며 개인화 성능이 입증된 통계가 아닙니다. 자연어를 주제/작업에 매핑하는 판단은 GPT 호스트가 담당합니다. 다른 대화방을 몰래 수집하지 않습니다.

## 실제 API와 연결
- `engine.mjs`: 검증된 불변 사건, revision CAS, 상태 재구성, 패턴과 근거, 최신 규칙 대체, 수치/문자/불리언 조건 충돌, 제안/전달 구분.
- `host-adapter.mjs`: 실제 기존 JHResearch/Personalization/Decision 런타임을 주입. 기존 `notices`, `rankWithGoal`, `reviewContext`, `selectProposals`를 호출합니다. 한 소유자·동일 범위만 허용합니다.
- `installed-runtime.mjs`: 이미 게시된 기존 런타임의 SHA-256을 대조한 뒤 불러옵니다. 다른 버전이면 임의 대체하지 않습니다.
- `store.mjs`, `cli.mjs`: 명시한 개인 파일만 원자적 저장. 기존 파일·손상 파일·동시 쓰기 충돌을 빈 기억으로 덮지 않습니다.
- `integration.test.mjs`: 기존 실제 런타임으로 조사→개인화→과거 결과 검토→제안→두 전달 기록→중복 억제를 검사합니다. 사용자/출처 데이터는 전부 합성입니다.
- `plugin-overlay/`: JH Secure Live 1.24.0의 증분 연결입니다. 기존 설정을 유지하며 새 패턴 skill과 메인 skill의 진입 경로를 추가합니다. `node host-pattern-guidance/sync-overlay.mjs`로 실행 파일과 소스 해시를 동기화합니다.
- `installed-runtime.test.mjs`: 실제 플러그인 폴더 구조에서 의존 모듈을 찾는지와 변경된 의존 파일을 거절하는지를 검사합니다.

게시 준비 검토에서 연구·패턴 모듈의 URL 정규화 차이로 전달 기록이 실패하는 문제와, Unicode NFKC 변환 후 유효하지 않은 문자열을 반환하는 문제를 추가 수정했습니다. 출처의 query 순서·추적 파라미터는 공통 규칙으로 비교하고 내용 해시는 계속 정확히 대조합니다. 문자열은 정규화한 결과에도 제한을 적용합니다.

## 상태와 개인정보
개인 파일은 `JH_Pattern_Memory_v2.json`, 스키마는 `jh.pattern-memory.v2`입니다. 파일 소유자 검사는 다른 개인 상태의 혼용을 막지만 인증을 대신하지 않습니다. 원문 대화, 환자·거래 내역, 인증정보를 저장하지 말고 짧은 목적 요약과 실제 원본을 찾을 수 있는 불투명 참조만 사용합니다. 민감성 필터가 모든 개인정보를 자동 식별한다는 보장은 없습니다.

v0.1 상태는 출처·소유자·정정 이력 보장이 없어 자동 이관하지 않습니다. 유효한 v2 상태를 찾지 못한 오류와 실제 부재를 구분합니다. 부재가 확인된 경우만 초기화합니다. 기존 연구/선택/판단/메모리아 저장소는 이동·변경하지 않습니다.

## 제안의 의미
출처는 실제 조회 URL·내용 해시·조회 시각·자료 종류를 갖고 있어야 합니다. 해시는 자료의 동일성 확인일 뿐, 내용의 진실성·HTTP 조회 사실을 독립 인증하지 않습니다. 출처 검토와 사적 정보가 없는 공개 검색어 작성은 호스트가 수행합니다. 외부 문구는 실행 지시가 아닙니다.

현재 목표와 필수 조건을 확인한 뒤, 기존 판단 학습과 같은 비교식 `benefit*confidence - .25*setupBurden - .25*ongoingBurden - .25*modeMultiplier*interruptionCost`를 사용합니다. 비교용 입력이지 만족 확률이 아닙니다. 같은 goal/topic/changeKey와 같은 URL·내용 해시는 제목/추적 URL/조회 날짜를 바꿔도 중복 안내하지 않습니다. 내용 변경은 재검토 대상이며 기본 7일 간격 또는 새로운 명시적 조사 요청을 적용합니다.

전달은 `handoff_attempted`이며 읽음·동의·만족이 아닙니다. 응답에 실을 제안의 전달 시도를 한 번만 기록하고 원래 영수증으로 복구합니다. 두 저장소 변경은 자동 원자적 트랜잭션이 아닙니다. 각각 CAS 저장·재조회가 필요하며 일부 실패는 부분 저장으로 표시하고 새 외부 작업을 실행하지 않습니다.

## 완료 경계
구현·로컬 검사, 실제 기존 모듈 통합검사, 플러그인 게시와 readback, 개인 상태의 저장·readback은 서로 다른 증거로 보고합니다. 테스트 통과는 실제 사용 만족도 향상이나 모든 대화방 자동 감시를 뜻하지 않습니다. 정기 검색·알림은 별도 실제 자동화 설정이 없는 한 실행하지 않습니다. APK/서버/HMAC/승인/미확정 작업 상태는 변경하지 않습니다.
